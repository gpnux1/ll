## GCC2.9 形状要点

1. **玩家侧 switch 源序 case1 在前** (case0/2 合并为 fall-through 臂)。
   目标分派链 `cmp #1 / beq case1 / cmp #1 / ble case0_2 / cmp #2 / bne default / b case4`
   只有 case1 写在最前才能生成; 把 case0/2 写在前面会多出一条分支 (M=187 vs T=186 条, 多 4 字节)。
2. **`u16 idx` 必须是 u16 类型局部**。u16 赋值产生 `lsls #16 / lsrs #16` 截断对
   (与同族 `sub_801E4D4`/`sub_801CA08` 一致); `s32` 或 `int` 会让截断消失。
   `case 1` 里另需 `s32 t` 中转 (t = ldrh+3; idx = t + ldrb) — 直接合并会重排 ldrh。
3. **`>0x70` 路径用 `anim = obj->animPtr; off = animSubIdx*2; anim += 8;` 两步**
   (同 `sub_801E690`), 使 `8 + idx*2` 折叠成 `ldrh r6,[r0,#8]`, 且保留 `r1` 作为
   目标槽 (目标 `ldrh r6,[r0,#8]` 而非 `ldrh r1,[r1,#8]`)。
4. **`animPtr` 不提取为函数级局部**。提取 `p = obj->animPtr` 会把 `ldr` 提前到
   `<=0x70` 判空之前, 破坏流程 (M=187 字节且池偏移全错)。
5. 玩家侧 `(s8)obj->fxKind` 与敌方路径一致比较; 目标入口用 `lsls#24/asrs#24`。
