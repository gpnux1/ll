## 关键事实 (已验证)

- `gDialogueActive`(0x030025D8, u8)、`gCameraTargetX`(0x030025F8)、`gCameraTargetY`
  (0x03002C3C)、`gChestObjects`(0x03004890) 均已命名; ChestObject = {flags,
  mapEntryIndex, spriteNodeIdx, interactionId, s16 x, s16 y} (8B)。
- Actor.x/y 的**所有**已匹配读取都是 ldrh (无 ldrsh) — 原始字段应为 u16 语义;
  本函数对 x/y 的算术全部带 (s16) 截断式扩展。
- 朝向同步模式 `targetFacing &= 7; facingDir = targetFacing;` 在已匹配的
  Chara_ProcessCmdStream 中编译为"一次 ldrb + 两次 strb", 项目标准写法即此。
- x 调整的 if 是**全嵌套**形式 (非 &&): 目标的失败分支去向不同
  (facing<1→y 段, facing>3→5..7 段), 且 `cmp #1; blt` 未被规范化为 `!= 0`,
  `cmp #5; blt` 未被规范化为 `> 4`。
- 目标寄存器布局: r4=actor r5=cmdStream/计数 r6=stateFlags/计数 r7=gActors/临时
  sb=x sl=y r8=idx ip=(s16)(x-16); `sub sp,#0xC` = 3 个 u16 spill (x-16, x+16, y-8)。
- 函数无 bl 调用; 候选语义与 ROM 一致 (人工核对每个分支)。

## 剩余卡点

1. **(s16) 算术扩展的存留**: 目标 `lsls #16; asrs #16; adds; lsls #16; lsrs #16`
   (扩展-加-截断全保留)。以 u16/s16/int 局部 + `(s16)x ± amount` 的一切写法,
   agbcc 都把扩展代数折叠掉。int 局部可保住 asrs 但丢失尾部 (u16) 截断并破坏
   边界检查的无符号 bhi。decomp-permuter 正在以 new_var 数组技巧搜索, 已到 11160。
2. RA 级联: idx 应落 r8、actor 应落 r4、stateFlags 应落 r3、gActors 应落 r7 —
   与 1 联动。
3. 位移条件必须写全嵌套 if (见上), 否则被范围折叠。
