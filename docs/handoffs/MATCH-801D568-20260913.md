## 2. 功能语义 (E2 级证据, 多消费者一致)

**伤害数字弹出**。战斗结算把伤害量写入 BattleObj+0xB2 (f_B2, 战斗函数 940-980 行处
`f_6C(HP) -= f_B2`), 本函数把该数值可视化:

1. `slot = gUnk_0300068C * 4 + 0x158` — 每个数字占 4 个 4bpp tile, 分配区在 OBJ VRAM
   0x0601 2C00 起的 7×4 tile (0x0300068C 记当前已弹出个数, 上限 7 与 gUnk_03000670[7] 对齐)。
2. 数值拆成百/十/个 3 位 (显示值夹到 ≤999, 但记录表存原始值)。
3. 前导零抑制: 百位为 0 → 该位写 0xFFFF; 十位为 0 且百位非正 → 十位写 0xFFFF。
   0xFFFF 作 (s16) 读即 -1, tile 源 `(s16)digit + 40` 落到字体表空块表项 39。
4. DMA3 拷 4 个 32B tile: 先 gUnk_0861A004 (字体表内另一空块, 表项 3, 清槽用) 到 tile[slot],
   再逐位 gUnk_08619FA4 + (digit+40)*32 到 tile[slot+1+i]; 每次 DmaCopy32(3,...)+DmaWait(3)。
5. 记录 {原始值, f_BF-16, f_C0-8} 到 gUnk_03000670[count], count++。
   消费者 sub_801D984 按 i<gUnk_0300068C 渲染 32×8 OBJ (Shape=1/Size=1, CharNo=0x158+4i,
   Pltt=0xF, Priority=0, VPos 加 sub_801768C 的弹跳偏移); sub_801DAA0 计时回收。

**字体表已解码验证**: gUnk_08619FA4 表项 39=空白, 40..49='0'..'9' (4bpp tile 逐像素比对),
表项 3 = 0x0861A004 = 空白。姊妹例证: sio_link.c 注释中 sub_8018BF8 同表作背景拼块。

## 3. 已复原的源码形状 (190 条指令形状/池布局/伪寄存器 home 全部对上)

见 `permuter/sub_801D568/candidates/v5_u16digits_case2.c` (推荐起手) 与 `base.c` (自包含版)。
要点 (每一条都被字节级证实, 不可省略):

1. `u16 digits[3]` + 所有读用 `(s16)` 视图:
   - `|=` 的读-改-写保持 u16 → `ldrh/orrs/strh`, 0xFFFF 走字面池 (若数组声明 s16,
     GCC 折叠成 neg 直接 store, 与 ROM 不符 — 关键判据);
   - 比较/除法/索引用 ldrsh (有符号提升 → 第二个除法走 __divsi3, 第一个 num/100 走 __udivsi3)。
2. `u16 i` 循环 `i <= 2` (锁存 `cmp #2; bls`, 自增截断 `lsls #16; lsrs #16`; `<3` 会变成 cmp#3;blo)。
3. **switch 必须含空 `case 2: break;`** — 3 个 case 才触发 balance_case_nodes 中点分裂,
   得到 ROM 的树形分发 `cmp1;beq / cmp1;bgt / cmp0;bne`; 两 case 版是链式 `cmp0;beq/cmp1;bne` (不符)。
4. 尾部三次独立 `gUnk_03000670[gUnk_0300068C].field_X = ...` (全局每次重读, 不能提局部指针);
   field_0 存 `arg0->f_B2` 原始值 (重新读内存, 非夹值局部)。
5. DMA 用 `DmaCopy32(3, src, dst, 32); DmaWait(3);` (与已匹配的 sub_804C638 同族同形状)。
6. ROM 字面池 8+3 词, 顺序: 0x0300068C, 0x3E7, 0x040000D4, 0x0861A004, 0x06010000,
   0x84000008, 0x03000670, 0x0000FFFF ‖ 0x08619FA4, 0x06010000, 0x84000008 — 候选已一致。
