## 3. RTL 深度分析与卡点根因

本次分析对编译器开启 `-da`（转储 flow, cse, lreg, greg 全流水线），在 RTL 级别精确定量了 `r5 ↔ r6` 互换的底层机制：

### 3.1 目标 vs 候选的寄存器映射
| 逻辑实体 | 目标汇编 (target.o) | 候选汇编 (mine.o) | 伪寄存器 (RTL) |
|---|---|---|---|
| `obj0` | **r4** (`adds r4, r0, #0`) | **r4** (`adds r4, r0, #0`) | Reg 22 |
| `var` | **r5** (`movs r5, #0xa/#0xf`) | **r6** (`movs r6, #0xa/#0xf`) | Reg 24 / 25 |
| `arg1` | **r6** (`adds r6, r1, #0`) | **r5** (`adds r5, r1, #0`) | Reg 23 |
| `base` | **r7** (`movs r7, #0x46/#0x28`) | **r7** (`movs r7, #0x46/#0x28`) | Reg 25 / 26 |

可用 callee-saved 寄存器按 `REG_ALLOC_ORDER` 遍历顺序为：`r4 -> r5 -> r6 -> r7`。
由于首个空闲寄存器分配给排序靠前的伪寄存器：
- **目标分配顺序**: `obj0` (取 r4) -> `var` (取 r5) -> `arg1` (取 r6) -> `base` (取 r7)
- **候选分配顺序**: `obj0` (取 r4) -> `arg1` (取 r5) -> `var` (取 r6) -> `base` (取 r7)

### 3.2 排序公式与 live_length 膨胀根因
GCC 2.9 `global.c:allocno_compare` 使用以下优先级排序：
$$\text{pri} = \frac{\lfloor \log_2(\text{refs}) \rfloor \times \text{refs}}{\text{live\_length}} \times 10000 \times \text{size}$$

在候选代码中：
- `arg1` (Reg 23): `refs = 2`, `live_length = 117` $\implies \text{pri} = \frac{1 \times 2}{117} \times 10000 = \mathbf{170}$
- `var` (Reg 24/25): `refs = 27`, 原始 `live_length = 56`。
  但在 `local-alloc.c:852` 中，遇到附带 `REG_EQUIV` 常量赋值的指令时：
  ```c
  if (REG_LIVE_LENGTH (regno) >= 0)
      REG_LIVE_LENGTH (regno) *= 2;
  ```
  因为 switch 中前 23 个 case（0x19..0x2F）均给 `var` 赋常数 15，`local-alloc` 连续翻倍了 23 次：
  $$\text{live\_length}(var) = 56 \times 2^{23} = 469,762,048$$
  这导致 $\text{pri}(var) = \frac{4 \times 27}{469,762,048} \times 10000 = \mathbf{0}$！
  因此 `pri(arg1) = 170 > pri(var) = 0`，GCC 必然优先将 `r5` 分配给 `arg1`，将 `r6` 留给 `var`。

### 3.3 为什么不能通过简化 switch 消除 23 次翻倍
实测证实：GCC 2.9 的 `stmt.c:group_case_nodes()` 会在构建跳转表前，对所有跳转到同一基本块且数值连续的 case 节点进行合并。
- 若将 0x19..0x2F 合并为单个 fallthrough 或 goto 同一 label，`count` 将从 25 跌破阈值 `CASE_VALUES_THRESHOLD` (5)，GCC 2.9 会直接退化为 if/else 比较二叉树（score 6580）。
- 因此，25 个独立的 `base = 40; var = 15; break;` 是迫使 GCC 生成 25 项跳转表（0x080450B8）的**唯一充分必要语法形式**。
- 我们实测了调整 0x30/0x31 在 switch 源码中的插入位置：在 pos 0~6 时 `pri(var) = 301 > pri(obj0) = 265`，导致 `var` 抢占 `r4`（score 100）；在 pos 7~23 时 `pri(var) = 150 < pri(arg1) = 170`，导致 `arg1` 抢占 `r5`（score 25）。
