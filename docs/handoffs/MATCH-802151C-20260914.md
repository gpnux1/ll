## 2. 机器契约与语义建模
该函数是战斗系统内菜单开启的前置校验、状态初始化与精灵装载队列调度器：

### 2.1 寄存器与参数契约
- `arg0` (`r0` -> `r8`): 菜单激活参数 / 控制命令号（存入 `gUnk_03000768`）。
- `arg1` (`r1` -> `sb`): 触发上下文战斗对象（传入 `sub_801FA10(arg1, 2)` 配置状态与动画）。
- 返回值 (`r0`): `0` = 菜单成功开启并进入装载就绪；`1` = 状态不满足（全员异常/无法行动或被中断标志拦截），放弃开启。

### 2.2 核心业务流程
1. **参战成员扫描**:
   调用 `GetObjPool()` 获取对象池基址 `pool`，调用 `sub_80489E8(pool, buf, 0, 0x7F)` 筛选玩家侧参战对象（写入局部缓冲 `buf`，最多 5 人），获得参战人数 `count`。
2. **异常/失能状态统计 (Loop 1)**:
   遍历 `buf[0..count-1]`，对应对象 `obj = pool + buf[i] * 0xC8`：
   若非 9 号槽（`obj->slot != 9`），调用 `sub_8045F10(obj, 0x3C)` 测试状态；若返回 `2`（处于异常/失能状态），`matchCount++`。
3. **临时/特殊槽位排除 (Loop 2)**:
   遍历 `buf[0..count-1]`，若发现 9 号槽成员（临时参战者），将有效参战人数递减 `count--` 并跳出。
4. **全员异常门禁判定**:
   若 `matchCount >= count`（有效我方全部失能，无法进行菜单指令交互）：
   - 调用 `sub_804C890(pool)` 执行同伴重定向/自救逻辑；
   - 检查 `sub_80187B4() & 0x4000`，若置位则调用 `sub_804C78C()` 执行清理；
   - 返回 `1` 退出。
5. **正常开启路径 (matchCount < count)**:

## 3. GCC2.9 关键形状与破局要点
1. **`sub_8021184` 签名升级为 `s8 mode`**:
   `sub_8021184` 内部对模式进行 `switch ((s8)b)` 处理。将其首参签名定型为 `void sub_8021184(s8 mode, u8 *obj)` 后，`sub_802151C` 中传入 `(s8)gUnk_03000768` 时 GCC 2.9 自然生成 `ldrb r0; lsls r0, #24; asrs r0, #24` 符号扩展，彻底避免了伪强制转换。
2. **Loop 1 指针算术操作数序**:
   `(BattleObj *)(buf[i] * 0xC8 + (u32)pool)` 显式使偏移动作在前，精确生成目标 `adds r1, r0, r7`（而非 `adds r1, r7, r0`）。
3. **Loop 3 消除冗余局部指针**:
   目标在条件内与条件外分别进行了 `pool + buf[i] * 0xC8 + 0xBC` 寻址，未将对象指针提升为常驻局部变量。代码中直接以 `((BattleObj *)(pool + buf[i] * 0xC8))->fxKind` 表达，释放了 `r5` 寄存器用于在循环前预先物化步长常量 `movs r5, #0xC8`。
4. **连续链式赋值生成对称寄存器装载序**:
   `gMenuObjLoadCount = gMenuObjLoadIdx = 0;` 在 GCC 2.9 中生成先取 `r1 = &gMenuObjLoadCount`、后取 `r0 = &gMenuObjLoadIdx`，再以 `r0` 存入 `Idx`、`r1` 存入 `Count` 的指令序，完美匹配原 ROM。
5. **`if (!flag) { ... return 0; }` 控制流极性**:
   使主执行流作为 direct fallthrough 内联展开，将异常清理分支 `sub_804C78C()` 归并至函数末尾统一返回 1 处，生成精确的 `bne 1b4` 前向远跳。
