## 2. 语义（已验证事实 E1+E2 + 强推断）

**状态机（`gUnk_03000716`）**

- `case 0`（启动）：取 `obj = gUnk_030006F8[0]`，按 `gUnk_0839B2A4[0]` 装配 `obj->headB`（`sub_801B81C`，与已匹配的 `sub_8020A0C` 同款调用，仅第 7 实参少了 `+ (arg1 << 5)`），置 `headB.f_2A = 3`、`state |= 0x2000`（"跳跃"位），状态置 1。
- `case 1`（广播）：若 `gUnk_030006F8[0]->headB.kindFlags & 0x800`（DMA 禁用中）则直接返回 0；否则对 `i = 1..count-1` 把源对象的整个 `headB`（0x30 B 结构赋值 → `ldm/stm ×4`）复制到 `gUnk_030006F8[i]`，各自 `state |= 0x2000`、`f_2B = posX`、`f_2C = posY`；播 `Sfx_Play(0x5A,0,0)`，状态置 2。
- `case 2`（收尾）：对每个未出场的队列对象（`slot != 0xFF`）：
  - 闪烁节拍：`headB.frameIdx <= 0x1E` 时 `(u16)(frameIdx % 6) == 0` → 置 `headA.kindFlags |= 0x200`（跳过帧构建），否则清掉；`frameIdx == 0x1F` 也置位。
  - 完成判定：`headB.kindFlags & 0x1000` 时 `sub_804C3A4(headB.palSlot, (u8)sub_801B954(&headB))`、`slot = 0xFF`、`state &= ~0x2000`、`gUnk_03000715++`。
  - 全部完成（`done >= count`）→ `Sfx_StopTrack(0)`、状态归 0、返回 1。

**强推断（命名建议，未落地）**

- 语义别名：`BattleFx_GroupCopyStep`（战斗效果"群体复制/同步"逐帧状态机）。

## 4. GCC2.9 形状要点（已实验证实的坑）

1. **`case` 顺序必须是 0,1,2**（源码顺序 = 块序）。写成 0,2,1 或 2,1,0 会改变寄存器分配与块序（0,2,1 曾误判为"尺寸匹配"的假象）。
2. **case 1 的 `for` 循环前面必须有 `if (gUnk_03000714 > 1)` 守卫**：目标是 `cmp r0,#1 / bls` 与 `cmp r6,r0 / bcs` 两条检查，缺守卫只剩后者（尺寸会假性匹配但指令缺失）。
3. **第 4 实参 `0xDA << 1` 必须经由函数级变量带入**（`int new_var; new_var = 0xDA << 1;` 放在 `switch` 之前，实参写成 `new_var`）。直接写字面量会让 GCC 在实参求值序里提前 `movs r3,#0xda / lsls r3,r3,#1`，把 r3 占死，迫使栈实参临时量改用 r4，最终多占一个 callee-saved 寄存器（r9）→ 前导码/尾码各多一条 `mov`（字节差 463）。
4. **case 2 的闪烁节拍必须写成三元表达式 + 长整型临时量**（本包最大突破，463 → 42）：
   ```c
   long new_var2;                                    /* 函数级声明 */
   ...
   new_var2 = ((f % 6) == 0) ? (obj->headA.kindFlags | 0x200)
                             : (obj->headA.kindFlags & (~0x200));
   obj->headA.kindFlags = new_var2;
   ```
   写成 `if/else` 两分支时 GCC 会把 AND/OR 两个块各自补上 `orrs`/`strh`（不共享），与目标的"共享 `orrs`/`strh` 尾块"不符；三元式让两个分支只算值、共享同一份 `orrs`+`strh`。注意临时量必须是 **`long`（32 位）**：改成 `u16` 反而退化（282）。
5. **局部量作用域/声明顺序**（`obj`/`i`/`result`/`tbl` 的多种排列、`obj` 合一或分 case、`newval`/`nv` 临时量有无、`&state` 指针化、`short`/`u32` 版 result）对本函数**不敏感**（均无改善）。
