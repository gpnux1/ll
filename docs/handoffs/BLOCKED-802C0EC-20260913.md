## 卡点 (二律背反)
`sub_801CE80` 的 arg3 (r3) 在两处被目标复用同一寄存器 r4:
- case19 (0x13): `adds r3,r4,#0`, 此时 r4 = 0 (来自 case0 的 `movs r4,#0` = CE80 arg4)。
- case24 (0x18) else: `adds r3,r4,#0`, 此时 r4 = 2 (来自 case24 `<=0x27` 分支的 `movs r4,#2` = mode 常数)。

但 case24 的 else 是通过 `cmp #0x27; bhi` **直接跳入**的 (跳转点在 `movs r4,#2` 之前), 因此
else 路径上 r4 实际是**不确定值** (可能为上一帧 case23 遗留的 `&gUnk_03000825`)。目标 asm 因此对
arg3 不做任何赋值, 直接复用 r4 —— 这是 GCC2.9 的寄存器复用/调度产物, 原始 C 在该路径上必然有一个
"值不可静态确定"的局部变量 (很可能是原作者的 bug 或原始源码里该变量在 else 路径未赋值)。

实验 (fndiff 归一化指令差, 仅统计真实指令):
| 候选 | 差 |
|---|---|
| 全字面量 (case19 arg3=0, case24 arg3=2) | 2 指令 (`movs r3,#N` vs `adds r3,r4`) |
| 局部 `u8 zero;` **未初始化**, case19/case24 都用 zero | **0 指令 (字节完全一致)** |
| 局部 `zero = obj->headA.palSlot` (case0, 定义语义) | 2 指令 (movs r4 排序) |
| `zero = 0` (case0) + case24 用 zero | 2 指令 (case24 值错误=0) |
| 用 obj->f_B4/f_B6/palSlot/headB.f_2A 等字段 | 11+ 指令 (多出 load) |
| `zero = 2` 于 case24 前 | 寄存器全局重排 (obj r7→r6), 44+ 块差 |
| 全局 gUnk_03000824 | 45 指令差 |

**唯一字节一致的 C 需要未初始化局部变量 (UB)**, 违反 AGENTS.md §2/§5 (禁止伪造数据流、要求可读
语义); 定义语义的候选始终差 1 个 `movs r3,#N` ↔ `adds r3,r4,#0` 或 1 条调度序。故保持 status 0,
不合入。仓库保持绿 (src 仍为 INCLUDE_ASM)。
