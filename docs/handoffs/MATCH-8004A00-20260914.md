## 2. 语义与业务逻辑 (E2 级证据)

`Chara_MoveBy` 与邻居 `Chara_SetTilePos` (0x080049C8) 属于同一组基础角色位置更新 API，由脚本虚拟机 `sub_804F280` 在解析角色控制指令时分派调用：

- 脚本中 `r1 > 0x77` 时执行相对位移：计算 `actorIdx = opcode - 0x78`，取接下来的 3 字节操作数作为 `isY`、`positive`、`delta`，调用 `Chara_MoveBy(actorIdx, isY, positive, delta)`。
- 业务处理逻辑：
  1. 根据 `positive` 标志判断位移正负：
     - 若 `positive != 0`，位移值 `val = delta`；
     - 若 `positive == 0`，位移值 `val = -delta`（补码取负，保存在 16 位容器中）。
  2. 定位角色实体指针 `ptr = &gActors[actorIdx]`（每项 `sizeof(Actor) = 0x28`，对应 `(actorIdx * 5) << 3`）。
  3. 根据 `isY` 标志选择作用轴：
     - 若 `isY != 0`，对纵坐标 `ptr->y` 累加 `val`；
     - 若 `isY == 0`，对横坐标 `ptr->x` 累加 `val`。

## 3. GCC 2.95 编译特征与匹配要点

1. **累加操作数顺序与临时变量 `temp`**:
   - 目标汇编生成的更新指令为：
     ```arm
     ldrh r0, [r1, #8]
     adds r0, r0, r3
     strh r0, [r1, #8]
     ```
     其中 `r0` 为已加载的坐标值，`r3` 为位移量 `val`。
   - 若直接写 `ptr->y += val` 或 `ptr->y = ptr->y + val`，GCC 2.95 在进行可交换二元运算规范化时，由于 `val` 分配的伪寄存器序号小于解引用加载的临时量，会触发 `swap_commutative_operands_p`，生成反向指令 `adds r0, r3, r0`（差 2 字节）。
   - 关键破解：引入局部变量 `u16 temp;` 显式分步读取与累加：
     ```c
     temp = ptr->y;
     ptr->y = temp + val;
     ```
     此时 `temp` 经加载后位于第一操作数，完美生成目标的 `adds r0, r0, r3`。
2. **符号与容器宽度**:
   - `val` 与 `temp` 必须使用 `u16` 类型，使 `rsbs; lsls #16; lsrs #16` 的截断展开与内存 `ldrh/strh` 严格对齐，不产生多余的符号扩展指令。
