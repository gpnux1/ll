## 卡点 (UB 二律背反, 与 BLOCKED-802C0EC 完全同型)
case30 (state 0x1E) 的 `sub_801CE80` arg3 (r3) 在目标里是 **`adds r3, r4, #0`** ——
r4 在本函数**从未被赋值** (目标 `r4` 首次出现就在 0x1f4 这条 `adds r3,r4,#0`)。
即原始 ROM 把 caller 遗留的 r4 不确定值直接当 arg3 传给 sub_801CE80 (原作者的 indeterminate bug)。

实验 (`.scratch/bcfn.sh`, 对称链接字节比对):
| 候选 | 差 |
|---|---|
| 局部 `u8 zero;` **未初始化**, 用于 case30 arg3 | **OK 936 bytes (字节完全一致, 但 UB)** |
| 局部 `u8 zero; zero = 0;` | 2 bytes (`movs r3,#0` vs `adds r3,r4,#0`, 同尺寸异字节) |
| `zero = obj->headA.palSlot;` | 635 bytes (多一次 load + 寄存器重排) |
| `obj->headA.palSlot` 直读 | 300 bytes (多 `adds r0,r5,#0; adds r0,#53; ldrb r3` 两条 + 池偏移) |
| `zero = (u8)gUnk_03000824;` | 754 bytes / 944 |
| `zero = obj->f_B4;` | 635 bytes |

**唯一字节一致的 C 需要未初始化局部变量 (UB)**, 违反 AGENTS.md §2/§5 (禁止伪造数据流、要求可读语义);
定义语义的 `zero = 0` 始终差 1 条 `movs r3,#0` ↔ `adds r3,r4,#0`。故保持 status 0, 不合入。
