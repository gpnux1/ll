## 2. 语义还原（强推断，E2 支持）

命中率判定。v 是「命中权重」：

```

       或 (s8)攻击者.fxKind == 1             (攻击型别 1)

否则:
    t = (攻击者.slot <= 0xA) ? 攻击者[0x8B] : 0
    v = 2 * (攻击者.agl - 目标.agl)
      + (攻击者.atc - 目标.def)
      + (arg2 - t)                            (arg2 = 0x50 = 80)
    v = clamp(v, 0x1E, 0x64)                  (30 .. 100)
    若 (s8)sub_804E76C(目标, 2, 8) >= 0:      (目标带 kind=2/val=8 的装备)
        v -= 50
    命中 = (Rng_LcgNext() % 100) < v
```

**注意 `v` 是有符号 `s16`**：`v -= 50` 后可为负（clamp 下界 30 → -20），比较按有符号 16 位进行。
这与「有 p 概率命中、概率钳制在 30%–100%、特定装备再降 50%」的玩法完全自洽。

## 4. GCC2.9 / agbcc 形状要点（本包核心产出）

按差异从大到小：

1. **`v` 必须是有符号 `s16`，不能写 `u16`**（差 7 B）。
   用 `u16` 时 `v -= 50` 展开为 SImode：`adds r0,r4,#0 / subs r0,#50 / lsls #16 / lsrs #16`；
   用 `s16` 时展开为 HImode 移位域：`lsls r0,r4,#16 / ldr r1,[pc] / adds r0,r0,r1 / lsrs r4,r0,#16`，
   常量池为 `0xFFCE0000` (= `-50 << 16`)。
   根因：agbcc 对 `u16` 局部做 SImode 提升，夹取赋值后 `v` 成为 SImode 值，减法走 SImode；
   `s16` 保留 HImode 语义，减法被展开成 MSB 对齐形式（neg 常量在移位域）。
   这是本包**唯一**需要形状调整的地方；`clone` 后 `(s16)v` 等冗余 cast 全部可删（等价）。
2. **`Rng_LcgNext` 必须宽化**：`((u32 (*)(void))Rng_LcgNext)() % 100`（差 16 B）。
   直接写 `Rng_LcgNext() % 100` 会插入 `lsls #16 / lsrs #16` 截断（`code_0.h:402` 声明为 `u16`，实际返回 32 位）。
3. **返回值必须走变量 + `else` 分支**：
   `if (cond) result = 1; else result = 0;` 而不是 `result = 0; if (cond) result = 1;`（差 16 B）。
   后者 GCC 会把 `movs rX,#0` 提前到 `bl Rng_LcgNext` 之前（并把 result 分配到 r5 这种 callee-saved 寄存器）。
   前者让 0 落在 `cmp` 前一条（r2），与目标一致。
4. 两个提前 `return 1` 条件必须写成 **`if / else if / else` 链**，GCC 交叉跳转会把三处 `result = 1` 合并成
   一个共享 `movs r2,#1` 块（早退 `beq` 直接跳进去），与目标一致。
5. 最终比较写成 `(s16)(...) < v` 的有符号 HImode 比较 → `lsls r0,r0,#16 / lsls r1,r4,#16 / cmp / bge`。

已排除的无效方向（均不改变字节）：局部声明顺序 6 种排列；`v -= 50` / `v = v - 50` / `v += -50` /
`(s16)` 各 cast 组合共 12 种；clamp 结构 6 种（三元 / 加 `(u16)` cast / 交换顺序 / if-else 链）；
返回值类型 6 种（`u8/s8/u16/s16/u32/int`）在 `v` 为 `u16` 时**完全无效**——它们不改变 `v` 的模式，只有 `v` 本身的符号性有效。
