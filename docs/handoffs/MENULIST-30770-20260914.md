# 类型分析 handoff: 0x03000770/0781 附近未命名簇 → gMenuList* (2026-09-14, agent=zcode-menulist-770)

## 任务
分析 IWRAM 0x03000770、0x03000781 附近未命名全局 (含空隙内未登记的 0x778) 并命名。

## 结论: 演出/菜单选择列表窗口的活动状态 (5 符号)
| 地址 | 新名 | 类型 | 语义 |
|---|---|---|---|
| 0x770 | **gMenuListCount** | u8 | 列表项数 (≤9) |
| 0x778 | **gMenuListItems** | u8[9] (**新登记**) | 列表项 id (槽号); 0x778..0x780 恰 9 字节, 与 Count≤9 精确吻合 |
| 0x781 | **gMenuListTop** | u8 | 滚动窗口顶项 (渲染行 = Top..Top+2) |
| 0x782 | **gMenuListCursor** | u8 | 选中项 (绝对下标) |
| 0x784 | **gMenuListRowBits** | u16 | 行样式位图 (bit n = 项 n 高亮/可选; 未置位 = 暗淡) |

## 证据链 (E2, 消费者交叉验证)
- **构建者 sub_8023820** (演出状态机, INCLUDE_ASM): 主循环 r6=0..7 扫描候选槽表 (0xFF 终止),
  逐项 `Items[0x778 + Count] = r6`, 过滤 (sub_8048934(obj, slot) ≥ 阈值) 通过者
  `RowBits |= 1 << Count`, 每次 Count++; 尾部条件追加 1 项 (obj[0x88] > 0x1F 时)。
  多个 case 的复位序列 = RowBits/Count/Cursor/Top 四字段全清 0。
- **同步者 sub_8021184** (C, fncheck OK) case6: 从 gMenuSlotStates[idx][1]/[2] (槽位顶项/光标)
  同步到 Top/Cursor, 槽位光标 ≥ Count 时吸附到末项 (Top = max(0, Count-3), Cursor = Count-1);
  case7 是第二平行窗口 (0x03000808/809/80A, 同角色, 本任务未命名)。
- **渲染者 sub_80256E4** (C, fncheck OK): `for (row = Top; row < Top+3 && row < Count; row++)`,
  行样式 = RowBits>>row & 1 ? (row==Cursor ? 调色2 : 调色0) : 调色1 (+0xB),
  行 y = (row-Top)*2+8, 9 列 × 2 行 —— 3 行可见的选择列表框。
- **使用者 sub_8024940** (演出): 比较 `x+3 < Count` (窗口滚动边界)。

## 工作假设
- RowBits bit 的确切含义 ("可选/有效" vs "已选标记") 来自过滤条件 (sub_8048934 阈值) + 渲染
  样式差 (置位才有高亮/可选两种, 未置位恒暗淡), 倾向"项有效性"; 具体业务未逐帧验证。

  两者未细分。
- 第二窗口 0x03000808/809/80A (含其 Count/Top/Cursor 同角色) 与 0x763-0x76E 邻区未命名符号
  属后续批次。
