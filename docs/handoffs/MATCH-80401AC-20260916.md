## 2. 机器契约与语义建模
本函数是**战斗全队逃跑演出状态机**（由 `BattleTask_Run` @0x08017E54 调用；单角色逃跑为姊妹函数 `sub_803FF54`）。
驱动状态 PC 为 `gObjActStep` (0x03000820)，内部按步骤流转。

### 2.1 依赖关系与生命周期
- **上游调用者**:
  - `BattleTask_Run`: 战斗主循环状态机在全队执行逃跑指令时调用，要求返回值类型为 `u32`（非 `u8`，避免在调用方生成不必要的 `lsls r0, #0x18` 截断，符合经验 90）。
- **被调子函数**:
  - `GetObjPool()`: 获取战斗对象池指针 `BattleObj*`。
  - `sub_80489E8(BattleObj *base, u8 *output, u8 mode, u16 flags)`: 收集参选对象槽位（此处 mode 0, flags 0x43 收集所有存活参战成员）。
  - `sub_8020974(ObjHead *head, u16 animId, u16 baseTile, u8 palSlot, u16 flags)`: 为目标角色加载逃跑动画。
  - `sub_8048310()`: 全队逃跑成功率检定（返回 1 成功，0 失败）。
  - `sub_801768C(s16 start, s16 delta, s16 totalFrames, s16 currentFrame, u8 mode)`: 浮点位移插值。
  - `sub_801CBA4(BattleObj *obj, u8 kind, u16 f2a, u8 palSlot, u8 arg5)`: 角色动作装配与复位（此处用于逃跑失败时恢复默认待机姿态）。
  - `sub_80187C0(u16 flags)`: 标志位操作（此处用于设置 0x1000 标志）。

### 2.2 全局变量与跨帧状态
- `gObjActStep` (`0x03000820`): 状态机主步骤 PC。
- `gObjActStepTimer` (`0x03000825`): 帧计时器。
- `gTargetSlotList` (`0x03000830`): 参选目标槽位列表（由 `sub_80489E8` 填充）。
- `gTargetSlotCount` (`0x0300083C`): 参选目标数。
- `gUnk_03000864` (`0x03000864`): 逃跑判定结果（0=成功，1=失败；与 `sub_803FF54` 共享）。
- `gObjActMoveFromX` (`0x0300086E`): 当前遍历对象的索引游标。
- `gUnk_03000870` (`0x03000870`): 各目标对象保存的原始 X 坐标表数组。在 `linker.ld` 与 `include/iwram.h` 登记。
- `gUnk_083988A8` (`0x083988A8`): 24-byte 动画条目表（`AnimEntry24`，偏移 0x14 为 `animId`）。

### 2.3 状态机流转流程
1. **case 0 (初始化并登记参演成员)**:
   - 调用 `sub_80489E8(pool, gTargetSlotList, 0, 0x43)` 收集我方所有成员；
   - 将各成员的初始 `posX` 快照存入 `gUnk_03000870[i]`；
   - 重置游标 `gObjActMoveFromX = 0;`、`gObjActStep = 0x31;`、`gObjActStepTimer = 0; break;`
2. **case 0x31 (逐个配置逃跑起跑动画)**:
   - 若游标 `gObjActMoveFromX < gTargetSlotCount`：
     - 取对象 `obj = pool[gTargetSlotList[gObjActMoveFromX]]`；
     - 查表 `gUnk_083988A8[obj->slot].animId`；
     - 调 `sub_8020974(&obj->headA, animId, (u16)(idx * 32 + 0xDA) * 2, obj->headA.palSlot, 0x401)` 为当前成员切换逃跑起跑动画；
     - `gObjActStep = 0x32;`
   - 若全员已配置完毕，流转至判定状态：`gObjActStep = 0x30; break;`
3. **case 0x32 (等待当前成员动画资源装载就绪)**:
   - 当 `obj->headA.kindFlags & 0x800 == 0`（DMA/装载完成）：
     - `gObjActMoveFromX++;`
     - `gObjActStep = 0x31;`（循环配置下一人）
4. **case 0x30 (检定全队逃跑判定)**:
   - 调用 `sub_8048310()` 进行逃跑概率检定；
   - 若成功 (==1) 则 `gUnk_03000864 = 0`，否则 `gUnk_03000864 = 1`；
   - 重置游标 `gObjActMoveFromX = 0;`，进入等待状态 `gObjActStep = 0x33; break;`
5. **case 0x33 (等待 50 帧后按结果分流)**:
   - 若 `gObjActStepTimer <= 0x31` 则自增；
   - 否则按 `gUnk_03000864` 分流：
     - 为 0 (成功) -> `gObjActStep = 0x34;`
     - 非 0 (失败) -> `gObjActStep = 0x36;`
     - `gObjActStepTimer = 0;`
6. **case 0x34 (成功向右逃离屏幕插值位移)**:
   - 若 `gObjActStepTimer <= 0x18` (25 帧)：
     - 遍历所有成员，各自以保存的 `gUnk_03000870[i]` 为起点，插值向屏幕右端 (256) 移动：
       `pool[gTargetSlotList[i]].posX = sub_801768C(savedX[i], 0x100 - savedX[i], 0x19, timer, 1);`
     - `gObjActStepTimer++;`
   - 超时后，遍历全员将 `pool[gTargetSlotList[i]].slot |= 0xFF`（脱离槽位）；
   - `gObjActStep = 0x35;`
7. **case 0x35 (成功收尾)**:
   - `gObjActStep = 0x38; result = 1; break;`
8. **case 0x36 (失败复位姿态)**:
   - 若游标 `gObjActMoveFromX < gTargetSlotCount`：
     - 调用 `sub_801CBA4(&pool[slot], 0, slot * 0x16 + 9, palSlot, 0)` 恢复该成员待机；
     - `gObjActStep = 0x37;`
   - 若全员已恢复：
     - 调 `sub_80187C0(0x1000)` 设置完成标志；
     - `gObjActStep = 0x38; break;`
9. **case 0x37 (等待当前成员待机姿态就绪)**:
   - 当 `obj->headA.kindFlags & 0x800 == 0` 时：
     - `gObjActMoveFromX++;`
     - `gObjActStep = 0x36;`（循环恢复下一人）
10. **case 0x38 (收尾完成)**:
    - `result = 1; break;`

## 3. 破局关键与 GCC2.9 调整
1. **返回值与函数原型必须为 `u32 sub_80401AC(void)`**:
   在汇编中结尾为直接 `mov r0, r8; pop ...; bx r1`，若声明为 `u8`，GCC2.9 会强制加入 `lsls r0, r0, #0x18; lsrs r0, r0, #0x18` 截断，破坏字节匹配；且调用方 `BattleTask_Run` 也要求其为 `u32` 返回（经验 90）。
2. **case 0x31 瓦片偏置公式**:
   汇编中目标生成的指令序列为：
   ```arm
   lsls r2, r2, #0x16
   movs r4, #0xda
   lsls r4, r4, #0x11
   adds r2, r2, r4
   lsrs r2, r2, #0x10
   ```
   这是 GCC2.9 对 `(u16)(x + K) * 2` 的经典 combine 强度归约（经验 193），书写为 `(u16)(gObjActMoveFromX * 32 + 0xDA) * 2` 即可完全一致命中。
3. **对象基址物化操作数顺序**:
   目标为 `adds r3, r0, r5` (offset + pool)，直接写 `&pool[i]` 会生成 `adds r3, r5, r0`。按经验 161 采用 `(BattleObj *)(gTargetSlotList[gObjActMoveFromX] * 0xC8 + (u32)pool)` 成功对齐操作数顺序。
4. **`AnimEntry24` 结构体建模**:
   定义 24-byte 结构体：
   ```c
   typedef struct
   {
       u8 unk_00[0x14];
       u16 animId;
       u8 unk_16[2];
   } AnimEntry24;
   ```
   并通过 `AnimEntry24 *entry = &gUnk_083988A8[slot]; entry->animId` 寻址，保留基址字面量与 `ldrh r1, [r1, #0x14]` 偏移装载，避免常数被折叠进字面池。
