## 4. GCC2.9 形状要点（本函数的三处硬坑）

匹配从"指令流 90% 对齐"到"字节全等"只差这三处：

1. **`off` 必须 `s32` 且写成两步减法**

   ```c
   s32 off = gObjActStepTimer;   // 正确
   off -= 0x64;
   ```

   写成 `s32 off = gObjActStepTimer - 0x64;` 时 agbcc 会**先做 24 位提取再减**（多出
   `adds r0,r1,#0` / `asrs` / `lsrs` 一组），指令数 +2。原因是减法要在 s32 域里完成、装回
   home 槽后再按需求做窄化；一步写法让窄化提前到减法之前。

2. **条件必须 `(u8)off <= 5`**

   目标生成 `subs r3,#0x64; lsls r0,r3,#0x18; lsrs r0,r0,#0x18; cmp r0,#5`（即掩码）。
   条件写成 `(off <= 5)`（s32 域比较）会退化成 `cmp r3,#5` 少掉两条掩码指令。
   同时 `subs r3,#0x64` 的值被**复用**去把 r3 原值覆写（`asrs r3,r3,#0x18`），所以条件里的
   `off` 必须真的是变量、且减法结果就在该变量里（即坑 1 的两步写法）。

3. **插值结果必须一次复合赋值**

   ```c
   gObjActSavedX = x = sub_801768C(...);   // 正确
   arg1->posX = x;
   ```

   目标为 `bl sub_801768C` → `lsrs r2,r4,#0x20 / lsls r0,r0,#0xc / lsls r0,r0,#0xc / ldr ...`，
   即先存 `gObjActSavedX`（strb r0,[r4]），**再用同一 r0** 做符号扩展后写 `arg1->posX`。
   拆成两句（`x = call; gObjActSavedX = x; arg1->posX = x;`）会让 agbcc 为两处各做一次窄化，
   多出两条 `lsrs/lsls` + 一次字面池取址（实测差 4 条指令 / 8 字节）。
   注意 `x` 必须是 `u8`（`s16`/`u16` 都会改变掩码宽度）。

工程实践：以上三条是在 `.scratch/opencode-80257d8/` 的本地判定脚本（见 §6）下，用
`off` 类型 × 声明形式 × 条件拼写 × 存储形式（约 150 个变体）小步枚举出来的；
diff 分数天然把三条坑混在一起（都落在 case5 区段），必须逐条分离才能归因。
