## 为什么之前"不可达 0"

旧 `permuter/sub_801F76C/base.c` **语义是错的**，不是纯 GCC2 指令选择问题：

1. 跳转表被当成 `r1`（减 6 后的值）索引，实际是按 **`v-6` 索引、结果写在 3 个共享臂**
   （`_801F868`/`_801F876`/`_801F87E` 分别置 `r3=3/2/1`）；
2. 老 base 把 case 0..7 逐个写 `r3=1`，**结果值 2 和 3 完全没有生成**；
3. `fxKind==2` 分支**完全缺失** `+0xA4` 的逻辑（`==0xE1→2`, `>0xDC→1`）；
4. 分支结构（`r0>1 → if(r0==2)`）与目标链不匹配。

语义错了，permuter 再跑也只是在错误空间里搜，2070 是天花板。

## 三个决定形状（缺一不可）

1. **外层 `switch (fxKind)` 必须带 `case 0: break;` 空臂。**
   目标链是 `cmp#1/beq/cmp#1/bgt/cmp#2/beq`——`bgt` 说明树根 `case 1` 存在左子树，
   即存在 `case 0`。去掉 case0 后 GCC 把 `else if` 优化成 `cmp#1/cmp#2` 二分
   （本函数 `else if (f>1){if(f==2)}` 的写法只能得到后者），链就差了 3 条指令。

2. **技能取值必须写成 `(0xA1 > 7 ? 0xA1 : skills[0xA1])`，且 `skills` 是 struct 数组成员。**
   目标是
   ```
   adds r1,r2,#0xa1 ; ldrb r0,[r1] ; cmp r0,#7 ; bhi
   adds r0,r2,#0x99 ; ldrb r1,[r1] ; adds r0,r0,r1 ; ldrb r0,[r0]
   ```
   —— 先算**基址** `arg0+0x99`、再算索引。写成 `arg0[0x99 + arg0[0xA1]]` 时
   GCC2 会把加法树归集成 `(idx + 0x99)` 再变址，得到
   `adds r0,r0,r2 ; adds r0,#0x99`（先索引后基址），多一条指令。
   用 **struct 数组成员 `obj->skills[i]`** 后 GCC 固定生成"基址 + 索引"两步，
   与 `sub_80489A4`/`sub_8048764`（都写 `ptr = arg0+0x99; ptr[val]`）形状一致。
   ⚠️ 这是本函数最大的坑：`arg0[0x99+idx]` 与 `((S*)arg0)->skills[idx]` 语义相同、
   C 源码等价，但 GCC2 生成不同指令顺序。

3. **`u8 r3 = 0;` 声明在 `s32 r0 = ...` 之前。**
   目标开头是 `adds r2,r0,#0 ; movs r3,#0 ; adds r0,#0xbc ; ldrb`——
   `movs r3,#0` 必须在 `ldrb` **之前**；把 `r3` 声明挪到后面会晚发射。
