## 语义 (E3)

1. `buf[0..4] = 0`；
2. 建随机序列：`sub_8018838(Rng_LcgNext())`，再丢弃一次 `Rng_LcgNext()`；
3. 遍历 `0x03000690` 对象链（节点 `key <= 0xFE`）：
   - 每节点数据对象 `+0xB2`（`dmgAmount`）逐帧 +1（与 `sub_8020AE4` 同一累加语义）；
   - 内部计数 `i` 递增（+1 经 u8 截断，即 `(u8)(i+1)`）；
   - `mode == 1` → `slot = i`，结束；
   - 否则按概率 `(n+1)*40 > rand%101` 判定（`n` = 该对象 `dmgAmount`），命中 → `slot = i`；
   - 未命中且 `n > 4`：把该对象 `memberIdx`（`+0xBB`）收进 `buf`；
   - 取 `node->next` 继续。
4. `count` = buf 收集数：
   - `count != 0`：`slot = buf[Rng % count]`，再在 `gUnk_030006A0`（16B/节点，`.data` 指向对象）里
     找 `memberIdx == slot` 的位次 `i`，命中则 `slot = i`；
   - `count == 0 && slot >= 0`：在 `gUnk_030006A0` 里找 `memberIdx` 与**当前节点**数据对象相同者。
5. 再 `sub_80489E8(pool, buf, 0, 0x100)` 收集候选槽表，命中 `memberIdx == slot` 则 `slot = buf[i]`
   （即池槽索引）。返回 `slot`。

## 四个决定形状 (GCC2.9)

1. **`n` 必须是未初始化局部变量**（ROM 真 UB，经验 58/155）。
   目标在 `movs r6,#0; cmp r6, r8` 处**直接读 r8**，而 r8 直到函数后半
   `mov r8, r0`（`sub_80489E8` 的返回值）才被写入。这是原 C 里 `u8 n;` 未初始化、
   GCC2 不删该读也不优化所致。给 `n` 预赋 0（`u8 n = 0;`）或改成 `u16`/`s32` 都会多一条 `movs`。
   两个查找循环共用这一个未初始化 `n` 作上界。
2. **循环体必须内联 `node->data`，不能抽 `u8 *obj = node->data;` 局部。**
   目标在 `Rng_LcgNext()` 调用之后**重新** `ldr r4,[r5,#12]`（0x70 处），说明源码是在
   概率判定里再次写 `node->data`。抽成局部队列变量后 GCC 复用调用前的值，少一条 load
   且寄存器分配整体错位（0.485 → 0.812 的分水岭）。
3. **尾部收集循环用 struct 数组索引 `((BattleObj *)pool)[buf[i]].memberIdx`。**
   裸写 `*(u8 *)(pool + buf[i] * 0xC8 + 0xBB)` 会让 GCC 把 `0xC8` 乘法留在循环体内
   （多 2 条指令 + 寄存器错位）。写成 struct 数组成员后 GCC 提前
   `movs r5,#0xC8` hoist 到循环外（0.812 → 0.977）。
   ⚠️ 桩结构体必须**恰好 0xC8 字节**，否则步长错成别的值。
4. **比较写 `(s8)slot == ...`**（常量/左操作数为 slot）才得目标 `cmp r3, r0` 的操作数序。

另: `i` 声明 **`s8`** 才生成目标 `mov r3,sp; adds r0,r3,r0` 的循环首形状
（`u8 i` 会得到 `mov r3,sp` 在循环外、`adds r0,r3,r1` 变体）。
