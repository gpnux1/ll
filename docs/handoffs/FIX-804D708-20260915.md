## 根因与判据 (E1+E2)
- `sub_804D708` 仅经分派表 `gUnk_0839CE38`（`sub_804DD70`）进入，**无直接 C 调用者** → 改签名不影响调用点。

- 本 handler 把第二参 `arg1` 原样透传给 `sub_80489E8` 首参 → `arg1` 语义即**池基址**，应声明 `BattleObj *`；旧 `u8 *` 触发 `incompatible pointer type` 警告（=用户所指“sub_80489E8 传入了 u8*”）。

- `sub_80489E8(arg1, ...)` → `sub_80489E8(pool, ...)`：消除该函数第 304 行的 incompatible-pointer 警告。

## 刻意保留的裸 cast（清理会破字节，与姊妹 sub_804DABC 不同）
本函数是 `sub_804D310` 的**纯克隆**，regalloc 敏感：
- ROM case0/case1 对 `obj+0xBD` 用**不同 dest 寄存器**：case0 `adds r0,r4,#0;adds r0,#0xbd;strb r1,[r0]`（dest r0），case1 `adds r1,r4,#0;adds r1,#0xbd;movs r0,#0;strb r0,[r1]`（dest r1）。
- 若改写 `obj->f_BD` / `obj->fxKind`，GCC 统一 dest 寄存器 → 实测 FAIL（140B，差异 @+0x3b/0x3c/0x5a/0x7c/0x7e/0x81..0x87）。
- 故 `((u8*)obj)[0xBC]`、`((u8*)obj)[0xBD]`、`*(u32*)((u8*)obj+0x88)` 均**按 ROM 保留**为裸偏移式（旧 functions.tsv 注记同类警告）。
