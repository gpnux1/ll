## 语义 (完整、已闭环)

传送/入口选择菜单的逐帧输入处理:

1. `gActors[0].stateFlags & 0x80` → 直接 return (跳过尾部)。
2. `gBlendCoefficients = 0x0C0F`; 按 `keys & 0x50`(R|DOWN) 前扫 / `keys & 0xA0`(L|UP) 后扫
   `gChoiceListPtr[cursor]`: 低 nibble ≤8 直用; >8 查 `gChoiceGateEventFlags[lo-9]`(u16[7]) 过
   `EventFlags_Test`, 开则取高 nibble。**扫描环的退出条件变量 `i` 恒为 0** (见下)。
3. cursor 变动 → `Sfx_Play(0,0,0)` + `gChoiceCursor=cursor` + `gChoiceSel=val&0xF` +
   `gChoiceDestTable` 组游走 (与已匹配的 ChoiceMenu_ResolveDest 同款) → 写 `gChoiceDestX/Y` +
   `gActors[1].x/.y(=destY-8)`。
4. cursor 未变且 A: `gChoiceSubIdx == gChoiceSel&0xF` → **传送分支**: 特例
   `gChoiceGroupIdx==4 && gChoiceSubIdx==0` 直接 return; 否则 `gChoiceMapSpawnRecordStream`
   记录游走 (8 字节 0xFF 终止字段), 取 `record[gChoiceGroupIdx] + gChoiceSubIdx*8` 的
   5 字段写 `gMapNpcSetId/gSpawnTileX/gSpawnTileY/gSpawnFacingDir/gMoveCmdSetId(u16 组合)` +
   `Sfx_Play(1,0,0)` + `gBlendCoefficients=0x1F00` + `gGameState=0xA`。
   不等 → **NPC 命令分支**: `pair=((gChoiceSubIdx&0xF)<<4)|(gChoiceSel&0xF)` 在
   `gChoiceGroupPairTable`(84×2B, 项0=(0x00,0x01)) 线性查 `(gChoiceGroupIdx,pair)` →
   `gCharaCmdStreams[cmdIdx]` → `Chara_SetCmdPtr(0,·)+Chara_StartMoving(0)` +
   `gChoiceSubIdx=gChoiceSel` + `ChoiceMenu_BuildList()` + `gChoiceCursor=0`。
5. **尾部 (除路径 1 和特例外都执行)**: 清 `gUnk_02005C84/CC4` 两个 u16[16];
   `gChoiceMapSpawnRecordStream` 游走到 record[gChoiceGroupIdx] (预检查 `off != gChoiceGroupIdx`);
   `off += gChoiceSel*8`; `Msg_DrawPoolSegment(gUnk_02005C82, base[off], 0xB)`。

## 实测命中的 C 形状 (不要再试错)

- 参数 `u16 keys` (产生 lsls/lsrs #0x10)。
- Actor 结构 `padA=8` 使 stateFlags 落 0x12。
- 门索引必须写成独立语句 `lo = lo - 9;` + `gateFlags[lo]`, 且 **lo 为 u32**:
  写成 `gateFlags[lo-9]` GCC 会结合成 `lsls #1; subs #0x12` (目标为 `subs #9; lsls #1`);
  lo 为 u8 会插入 u8 cast。
- `gChoiceSel = val & 0xF; val = val & 0xF;` 双表达式 → CSE 成 临时 r0 + `strb r0` + `adds r5,r0`。
- `gChoiceSubIdx` **直接读全局**, 不要缓存到局部: 记录游走的 `base[off]` char 读会使
  缓存失效, 目标在游走后经 sb 重载。
- `gMoveCmdSetId = base[off] + (base[off+1] << 8);` — **加号**; 用 `|` 会生成 orrs。
- 搜索环: `k++; m = k; k++;` 两段独立 u8 自增 (两个 u8 writeback), 读 `table[m]`/`table[k]`,
  出口 `k = k >> 1`。cmdIdx/k 是同一个变量 (初值 1 = 默认 cmdIdx, 项 0 命中 → 0)。
- 尾部两个清除环的计数器与游走 off 共用同一个 u16 变量。
- `gUnk_02005C84/CC4` 清除环: `do { *tilePtr++ = 0; off++; } while (off <= 15);`
  (GCC 折叠掉恒真的前置检查)。

## 未解卡点 (唯一结构性差异)

**backward 扫描环**: 目标把 [门测试(call)+环条件 cmp r6] 内联在环体尾
(`[top][body][gate][check: beq top]`, 回边为分支), 我的全部形状 GCC 都把 [gate+check]
hoist 到环体前并 fallthrough 回边。已试并排除:
do-while / `for(;;)`+`if(i!=0)break` / continue 形式 / `while (i==0)` (守卫被 i==0
常量折叠, 验证了 roll+duplication 机制但布局不变) / 嵌套 if-else。
forward (while 形式) 完全命中, 说明机制理解正确; 差异疑与 loop.c `move_movables`
的 threshold `(loop_has_call?1:2)*(1+n_non_fixed_regs)` 或 jump.c 块序有关。
**先解此布局 — A 路径/tail 的 RA 级联 (off 应落 r5、&gChoiceSubIdx 应落 sb、
A 路径只 hoist 2 个地址而非 5 个) 疑似全部由它引起** (global-alloc 在最终 RTL 上跑)。

可试: (a) 以 -O1 对比 target 逐 pass 二分 (agbcc 无 per-pass dump, 需改用
flag 组合二分); (b) 检查 loop.c 对"环条件不变量"的特殊处理是否被
`i` 的三用阻止/触发; (c) 把 backward 的环条件改为非常量敏感的等价形式。
