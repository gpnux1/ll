{
    u16 original;   /* = *(u16*)(obj+0x70), 后续按 s16 用 */
    u8 *data;
    u8 id;
    u8 amount;

    original = *(u16 *)(obj + 0x70);
    data = obj + 0x70;
    data += 0x29;
    data += index;
    id = *data;                                   /* obj[0x99+index] */
    amount = gUnk_08093418[id * 5 + 4];           /* 0x08093418 表, 行宽 5 */

}

## F. 已尝试且排除

**唯一改变的因素 = 源码结构/类型/求值顺序; 结果一律是尾部 4 条指令的寄存器 home 不变或只差那条 copy。**

已系统穷举并**排除** (共 >10,000 个变体, 全部以 bc2 逐字节或 norm/score 逐指令判定):

1. width/tail 表达式: `(s16)original - amount` / `- (s16)amount` / `- (u8)amount` / `- (int)amount` / `- (s32)amount` / `- (u32)amount` / `(s16)(original-amount)` / `(u16)(...)-0x8000` / `original-amount` / 反向比较 `amount > (s16)original` / `amount >= ...` / `return X >= 0` 等。
2. 局部中转变量: `s16/int/s32/u16/u32/u64/s64/u8/s8` × 赋值时机 (load 后 / if1 后 / if2 后) × 赋值形式 (`v=amount` / `v=(s16)amount` / `v=(u8)amount` / `v=amount+0` / `v=amount*1` / 自赋值 / `(void)v`)。
3. 复合赋值 vs 两步赋值: `amount >>= 1` / `amount = amount >> 1` / `amount = amount / 2` / `amount = (u8)(amount>>1)`; 同理 `-2` 形式。
4. 双臂 if/else (phi): `val = cond ? amount>>1 : amount;`(实测确实产出 `adds r1,r4,#0` — 见 be4; 但移位落 r1 而非 r4, 且目标无 else 分支的 `b`); 各种 phi 排布。
5. 变量兼职 (经验 87): 复用 `id`/`data`/`original` 承载 amount; 一个变量先装 1 再装 amount (目标那条 copy 要求值跨基本块, 本函数只有一个汇合点, 未复现)。
6. 类型矩阵: amount/original/中转 的所有 8/16/32/64 位组合; `register` 存储类; 声明顺序 (amount 先/后)。
7. 编译 flag: `-O2` 与 `-O2 -g` (Makefile 实际选项) 结果相同; permuter 全 flag 集。
8. permuter 多轮 (>4 万次迭代, 分别以 e3 / m4 / u64 / be4 / y3 为 base): 只在以 **u64 limit** 为 base 时跑出字节一致 (score 5), 其形态即 E 节的 `&limit`/聚合体凑形; 自然形状 base 从未降到 210 以下。

**排除理由**: 目标尾部 `adds r1,r4,#0` 要求 amount 的伪寄存器与"参与相减的 s16 被减数"处在**不同的 home 寄存器**且由一个 copy 相连。本函数只有一个汇合基本块, 自然 C 会让两者 coalesce (或让移位直接写入同一寄存器), 因而这条 copy 在自然写法下恒不出现。全 ROM 范围内该"copy-into-r1 后紧接 subs r0,r0,r1"形状只出现 2 次 (本函数 + 已匹配 Chara_GetDrawX), 且 Chara_GetDrawX 的 copy 来自不同机制 (r2 = 常量 −256 的拷贝), 不能反推本函数源码。
