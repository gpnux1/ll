## 匹配关键 (GCC2.9/agbcc 形状, 供姊妹函数参考)

1. **无 `entry` 指针变量**: 调用点直接写 `gUnk_08393B28[idx].field_X` (4 处) —— GCC 把 idx*20 CSE 进 r3、
   基址常量驻留 sl, 每字段地址重算 (`mov r4, sl; adds r4, #4; adds r3, r3, r4` 的怪形即来源于此)。
   写成 `entry = &gUnk_08393B28[idx]` 缓存指针会得到完全不同的分配 (11203→2800 分差的主因)。
2. **case 顺序 = 0,5,1,2,3,4** (源码顺序决定块布局; case0/5 共享 u16 截断尾, case3/4 共享 f_C3 尾)。
3. **case0/5 内 `flag = ...` 在 `if (f_AB)` 之前**; case3/4 内 `flag = 2` 在表项读取之前。
4. case3/4 的 `f_B4/f_B6` **直接赋值**, 不要 v1/v2 临时 (姊妹 sub_801CE80 需要 v1/v2, 本函数不需要 —— 伪寄存器编号会变, p/base/v1 三角换位)。
5. case3/4 的 idx 加法结合: `base + (kind + arg5)` (括号强制 kind+arg5 先算)。
6. default (kind>5) 路径 idx/flag 未初始化, 读旧 sb/sl —— ROM 真 UB, 已有调用者不会触发。
7. 分数轨迹: 11203 (entry 缓存版) → 4120 (直接索引+case重排) → 2890 (flag 前置+括号) → 2800 (免临时) = 指令全对齐, 字节级 BYTE-IDENTICAL (双侧按 0x0801CA08 链接施加重定位后 cmp)。
