## 3. 语义 (已验证事实 + 强推断)

- **已验证**: 返回 u8 位掩码 {1,2,4,8}，是攻击方 obj 的“效果属性标签”，喂给 `sub_8047D28(defender, mask)` 做克制/抵抗分级（1=×2, 2=÷2）。
- **强推断**: 顶层 `fxKind`/`slot` 决定“属性来源”：玩家侧(slot≤0xA)按效果类型从「装备/技能效果表」查位；敌方/特效(slot 12..112)直接取动画数据块 `animPtr[0x18]` 的预存属性字节。
- **工作假设(需 E3)**: 0x0839D81A[] 是「装备位→基础属性掩码」ROM 表（以 equipSlots[0] 索引），case0 再叠加 4 个 status-effect 位（0xE..0x11 异常/增益）。字段语义待 owner 用更多消费者确认。

## 4. 发现的 bug（相对 codex base.c，E1 直接证据）

1. **case0 / `0x11` 判定**（ASM 68–79）：`sub_804E6DC(obj,0x11) < 0` 走 `b FC2` 返回 **当前 result**（已含 `|=2/8/4`），**不是 return 0**。
   - codex base.c:38 `if (...0x11) < 0) return 0;` → 应改为 `if (...0x11) >= 0) result |= 1;`（两条路径都落到 return result）。
2. **case1 跳表**（ASM:144 `case 34: .4byte _08047F20`，F20=`movs r4,#8`）：`result=8` 的 case 是 **{32, 34}**。
   - codex base.c:68-70 只有 `case 32` → **漏 `case 34`**。

（另：`sub_804E6DC` 返回类型确认为 `s8`，与 include/code_0.h:1074 一致；`(s8)` 强转与 ASM 的 `lsls#0x18;cmp;blt/bge` 对应。）

## 5. 剩余差异与下一步（owner 形状迭代用）

- 我的 cand.c（语义正确）与 codex base.c 均 ~544B，目标 516B。
- **主因**：顶层 `fxKind` 三向在 ROM 中是**显式比较梯**（先 `cmp #1/beq`，再 `bgt`→`cmp #0/beq`→`cmp #2`），但 GCC2.9 把 `switch(k){case0,1,2}` 编成了 **3 项跳表**（多出 ~28B + 布局变化）。
  - 候选修法 A：保持 `switch` 但调整 case 源码顺序 / 加 `if` 早退以复现比较梯。
  - 候选修法 B：显式 `if(k==0)..else if(k==1)..`（我的 cand2.c 试过 → 245 diff，regalloc 变差，非直接可行；需配合 |=8/|=4 后的 u8 就地截断 quirk）。
  - case0 内 `result |= 8; result=(u8)result;` 与 `|=4` 后的 lsls/lsrs 0x18 截断是 GCC2.9 关键形状点，须逐一复现。
- 另两处 `bl sub_8047DC8`（code.s 133948/134094）的调用者语义建议 owner 一并复核（是否同为属性查询）。
- **形状实验记录 (qwen, 隔离)**：
  - cand.c（`switch(fxKind)` + 内层 `switch` + `break`/单出口，含 §4 修正）= **179/544 diff**，目前最优基线。
  - cand2.c（顶层改 `if k==0/1/2` 梯 + 显式 `(u8)result` 截断）= 245/536（regalloc 变差）。
  - cand3.c（顶层 `if` 梯 + 内层改 `return` 早退）= 375/536（**更差**：ROM 内层 switch 是“置 r4 → 跳 FC2 共同出口”，非 early-return；cand.c 的 `break`+单 `return result` 才贴合）。
  - 结论：体积 +28B 主要来自 GCC 对 `switch(fxKind)` 上跳表 vs ROM 显式比较梯；需 permuter 在“比较梯/声明顺序/home”上系统搜索，非几轮手工可收敛。
