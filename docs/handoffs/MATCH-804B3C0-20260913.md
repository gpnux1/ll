## 语义

调色板动画表 (gBgPalAnim/gObjPalAnim) 某槽的 opcode1 "流式"逐帧推进:

1. 按 `ctrl` bit4 (0x10) 决定往返方向: 置位则 `counter++`, 增到 `period-1` 后清 bit4;
   否则 `counter--`, 减到 0 后置 bit4。
2. `entry->shift = 0`, 再由 `period>>1` 反复右移 +1 计步 (上限 7) 得插值移位量。
3. 调 `sub_804B56C(src + palSlot*32, dest + slot*32, period-counter, &entry->dR)`
   → 逐 16 色 `src + delta*weight>>shift` 插值 clamp 写 VRAM。

## 关键形状突破 (GCC2.9 / agbcc) —— 附全局分配教训

同一 `battle_anim.c` 的两个 opcode 函数卡点相反, 分开记:

### sub_804B3C0 卡点 = global-alloc 的 flags/count home 交换

前 agent 卡在 "flags r3/r5, count r5/r3 正好互换 + 掩码目的寄存器" 差 ~117B。根因 (经验 245 的
`allocno_compare` 优先级) 被以下三点一次性解开:

1. **不要把 `entry->ctrl` 存进 `flags` 变量**。直接写 `if (entry->ctrl & 0x10)` 和
   `entry->ctrl = entry->ctrl & mask / | 0x10`, 让 GCC 把 ctrl 的 CSE 值放 r5、`count` 放 r3
   (与目标一致)。一旦声明 `int flags = entry->ctrl;`, flags 抢 r3、count 退 r5 (差 255 → 目标反)。
2. **掩码必须是变量** `int mask = ~0x10;`: 否则常量被窄化成 `movs #0xEF` (规则 76)。
   目标仍是 `movs #0x11; negs r0; ands r0, r5`。
3. **循环变量必须 `unsigned short v` 且二元赋值分写**:
   ```c
   unsigned short v;
   ...
   v = entry->period;
   v >>= 1;
   ```
   只有宽类型 + 分写才能保住循环内 `v = (u8)(v >> 1)` 的**截断临时** (`lsrs r0; lsls #24;
   lsrs`); 直接 `v = entry->period >> 1` 或 `v` 声明为 int/u8 会被 GCC 折叠成 in-place `lsrs`,
   差 2 指令。(permuter 从 205 → 50 → 手工合成 0。)
4. 指针按**字节**偏移: `(u16 *)((u8 *)src + ((s8)entry->palSlot << 5))` (16色×2=32), 否则
   `u16*` 会把偏移再 ×2 出 `<<6`。

### sub_804B4D0 卡点 = expand_end_loop 循环翻转 + 裸字节字段

见 MATCH-804B4D0-20260913.md。核心: shift 循环必须是被 `expand_end_loop` 滚到循环尾的形态
(`if ((v >>= 1) != 0) do {...} while ((v >>= 1) != 0)`), **且 shift 字段必须裸字节访问
`((u8 *)entry)[0xF]`** —— 写成 `entry->shift` 会让 GCC2 放弃该翻转 (差 ~1400)。
