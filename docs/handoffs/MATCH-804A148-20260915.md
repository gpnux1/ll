## 2. 机器契约与语义建模
该函数是战斗主任务循环（`BattleTask_Run`）进入回合状态结算（`case 13`）时的初始化例程。它收集全场处于异常状态的角色、维护玩家侧状态计时器、并基于条件与随机概率筛选本回合待行动角色序列。

### 2.1 依赖关系与生命周期
- **上游调用者**: `BattleTask_Run`（`case 13` 触发 `sub_804A148()` 后置状态为 `14`，`case 14` 逐帧执行 `sub_804A368` 状态机直至返回 `1` 推进至 `case 15`）。
- **被调子函数**:
  - `GetObjPool()`: 获取 `BattleObj` 池首地址；
  - `sub_80489E8(pool, buf, mode, flags)`: 参战角色槽号筛选器（`mode=0` 为我方 0..4 槽，`mode=1` 为敌方 5..11 槽）；
  - `sub_8048C80(obj)`: 角色行动条件评估函数；
  - `Rng_LcgNext()`: 伪随机数生成器；
  - `__umodsi3`: 无符号整除求余。

### 2.2 全局变量与状态簇 (`0x0300097F..0x030009BD`)
在 `linker.ld` 与 `include/iwram.h` 中完成语义建模与符号登记：
- `gTurnStep` (`0x0300097F`): 回合阶段状态机当前状态，本函数置初值 `1`。
- `gTurnAilSlots` (`0x03000988`): 异常状态角色槽号缓冲（容量 12 字节）。
- `gTurnAilCount` (`0x03000994`): 异常状态角色总数。
- `gTurnAilIdx` (`0x03000995`): 异常状态遍历游标（由下游 `sub_804AA2C` 复位，`sub_804A368` 消费）。
- `gTurnAilMask` (`0x03000996`): 异常状态综合掩码（按 `statusAil` 进行 `|=` 累积）。
- `gTurnActSlots` (`0x030009B0`): 回合待选行动角色槽号缓冲（容量 12 字节）。
- `gTurnActCount` (`0x030009BC`): 回合待选行动角色总数。
- `gTurnActIdx` (`0x030009BD`): 回合待选行动角色遍历游标。

### 2.3 核心业务逻辑
1. **重置异常状态汇总**:
   `gTurnAilCount = 0`, `gTurnAilMask = 0`。
2. **扫描参战角色**:
   - `count0 = sub_80489E8(pool, buf0, 0, 0xFF)`：收集玩家侧参战角色。
   - `count1 = sub_80489E8(pool, buf1, 1, 0xFF)`：收集敌方参战角色。
3. **统计玩家侧异常 (Loop 1)**:
   遍历 `buf0`，若 `pool[buf0[i]].statusAil != 0`：
   `gTurnAilMask |= pool[buf0[i]].statusAil;`
   `gTurnAilSlots[gTurnAilCount++] = buf0[i];`
4. **统计敌方异常 (Loop 2)**:
   遍历 `buf1`，若 `pool[buf1[i]].statusAil != 0`：
   `gTurnAilMask |= pool[buf0[i]].statusAil;` （★原版 ROM 复制粘贴 bug，见第 3 节）
   `gTurnAilSlots[gTurnAilCount++] = buf1[i];`
5. **维护玩家侧 `0x10` 状态计数器 (Loop 3)**:
   遍历玩家侧角色，若 `pool[buf0[i]].state & 0x10` 置位：
   - 若 `pool[buf0[i]].pad_BA[0] <= 1`，计数器自增 `+1`；
   - 否则状态持续期满，清除 `state &= ~0x10` 并清零计数器 `pad_BA[0] = 0`。
6. **筛选行动候选角色 (Loop 4 & Loop 5)**:
   - 以标志 `0x2C` 再次调用 `sub_80489E8` 筛选行动候选：`count0`（我方）、`count1`（敌方）。
   - 若我方仅 1 人（`count0 == 1`）：直接将 `buf0[0]` 存入 `gTurnActSlots[gTurnActCount++]`。
   - 若我方非 1 人：清零 `gTurnActCount = gTurnActIdx = 0`，对各槽对象调用 `sub_8048C80`，评估为 1 者入选 `gTurnActSlots`。
   - 敌方角色遍历：以 40% 概率（`Rng_LcgNext() % 100 <= 39`）入选 `gTurnActSlots`。
7. **推进状态**:
   置 `gTurnStep = 1`。

## 3. 破局关键与原版代码特征

### 3.1 原版 ROM 复制粘贴 Bug
在 Loop 2（敌方异常状态统计）中：
反汇编明确显示读取了 `sp + r5`（即我方 `buf0[i]`），而非 `sp + 8 + r5`（`buf1[i]`）：
```arm
	mov r1, sp
	adds r0, r1, r5
	ldrb r0, [r0]         @ r0 = buf0[i]
	muls r0, r4, r0
	adds r0, r0, r6
	adds r0, #0xb8
	ldrh r1, [r7]         @ r1 = gTurnAilMask
	ldrh r0, [r0]         @ r0 = pool[buf0[i]].statusAil
	orrs r1, r0
	strh r1, [r7]         @ gTurnAilMask |= pool[buf0[i]].statusAil;
```
这是原版游戏开发者在编写敌方逻辑时，直接复制了玩家侧逻辑，修改了外层 `if` 与 `gTurnAilSlots` 赋值，但遗漏修改了 `|=` 运算操作数的典型 copy-paste bug。在 C 代码中保留此语义注释。

### 3.2 链式赋值对齐存储与寄存器顺序
在 `else` 分支中清零 `gTurnActCount` 与 `gTurnActIdx` 时：
若分别独立书写 `gTurnActCount = 0; gTurnActIdx = 0;`，GCC 2.95 会因变量声明和语句顺序生成先向 `gTurnActCount` 存值、后重新加载 `gTurnActIdx` 的分散操作。
改用右结合链式赋值：
```c
gTurnActCount = gTurnActIdx = 0;
```
GCC 2.95 精确生成：
```arm
	ldr r2, =gTurnActCount
	ldr r1, =gTurnActIdx
	movs r0, #0
	strb r0, [r1]
	strb r0, [r2]
```
与原目标汇编完全一致。

### 3.3 `((u32 (*)(void))Rng_LcgNext)()` 规避 16 位截断
由于历史原因，`include/code_0.h` 中将 `Rng_LcgNext` 声明为 `u16 Rng_LcgNext();`。在没有显式强转时，调用处会产生 `lsls r0, #16; lsrs r0, #16` 截断指令（导致整段代码膨胀 8 字节并引起全 ROM 偏移）。
通过在调用点添加与同文件姊妹函数（`sub_804473C`, `sub_8046480`, `sub_8048C80`）相同的标准强转：
```c
if (((u32 (*)(void))Rng_LcgNext)() % 100 <= 39)
```
消除了多余的截断指令，尺寸精确回归 544 字节。
