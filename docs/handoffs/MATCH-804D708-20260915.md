## 3. 为什么会出现 `movs r2, #0 因为赋值从未使用`？
- **原因**：当直接写 `obj->fxKind = 0;` 和 `case 1: obj->f_BD = 0;` 时，GCC 2.9 的 CSE (公共子表达式消除) 认为同一结构体内的两次常量 0 赋值可以复用寄存器，于是选用了空闲的 `r2`（生成 `movs r2, #0; strb r2, [r1]`并在末尾复用 `strb r2, [r0]`）。
- **破局解法**：使用 `u8 *flag = &obj->fxKind; *flag = 0;`（与同文件 `sub_804D840` 相同手法）。通过指针间接写断开 GCC 对同一结构体常量的跨基本块 CSE 假设，使得两处写入均使用当前死寄存器 `r0` 进行独立的 `movs r0, #0; strb r0, [r1]`，与原版 ROM 字节完全一致。
