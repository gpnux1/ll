## 2. 功能语义 (E2 级证据, 逐态)

脚本参数 `data[2..5]` → `x = pc[2]` (列), `y = pc[3]` (行), `count = pc[4] | pc[5]<<8`
(token 数), `tokens = pc + 6`。

| 态 | 行为 |
|---|---|
| 0 | 初始化: cursor=0; 绘制坐标 (x,y); 若 `gScriptVmFlags&0x10`(窗口BG请求) 未置, 则清 0x02005800 与 0x0600F800 各 0x400 半字, 开 BG0, 配 BG0CNT = CharBase2/ScBasep31 (0x1F08); 然后 `sub_80501B8(tokens, 0x800, 0x10)` 登记窗口块, 置 flags\|=0x40, 进态 5 |
| 5 | 若 `flags&0x40`(tile DMA 待刷) 已清, 读 token 高字节 `tokens[cursor+1]<<8` 并按 **高字节** 分派: 0x07→态6; 0x09→X 复位为 x, Y+=2 (换行); 0x0F→态8; 0x08→X=x,Y=y 并清 0x02005800, 再 `sub_80501B8(tokens+cursor+2,0x800,0x10)`; 0x0A→等待: 记帧数 `gDialogTimer=tokens[cursor]`, 进态 11; 0x02→动画: `gTileAnimFrameIdx=0; gTileAnimCharIdx=tokens[cursor]`, 预载 `sub_8050434(0x0862D574 + charIdx*18, 0x6F1E)`, 若 `gTileDmaCount!=0` 则置 flags\|=0x40 否则画字并 X++, 进态 12; 0x01/03/04/05/06/0B/0C/0D/0E→空 (保留 token); default→画字 |
| 6 | 光标闪烁: 若 `sub_80187E8()&0xF000 == 0x1000` (按键按下) 则回态 5 并写 0xC001; 然后 `gDialogTimer = (gDialogTimer+1)&0xF`, 在窗口第 X+0xD4 格写 `0xB266 + (gDialogTimer>>3)` (0/1 闪烁) |
| 8 | 收尾: 相位=0; `*pScriptCursor += count*2 + 6` (跳过整个 token 块); 若窗口BG请求未置则关 BG0 |
| 11 | 等待: `gDialogWaitFrames(0xE74) < gDialogTimer` 则 ++, 否则回态 5 |
| 12 | 动画续画: 再调 `sub_805063C`; 返回 0 则 X++, 否则回态 5 |
| default(1-4,7,9,10) | 空 |

**default 画字路径** (token 高字节既非 0x01..0x0F 者), 三种子形:
- `tokens[cursor+1] & 0x10` 置位 (tile 重定向): `tile = (hi<<8 | lo) & ~0x1000`; 若 `tile > 0xDF`
  则在 `gTileDmaAllocTable[0..gTileDmaCount)` 线性查 `tile` 取下标 i, 写 `tile=(i+0xE0)*2`;
  否则 `tile *= 2`。在 tilemap 第 `Y*32+X` 与 `+0x20` (下一行) 写 `0xB000+tile` / `0xB001+tile`。
- `tokens[cursor] != 0` (普通字): 同上但 tile 直接 = `lo*2`。
- `tokens[cursor] == 0` (空格): 两格写 `0xB001`。
都 `X++`。

**常量语义**: `0xB000 + tile` / `0xB001 + tile` = BG0 16 色 tilemap 图块项
(0xB000 = 高调色板页 bank); `0xB266 + n` = 光标图块; `0xC001` = 按键提示图块;
`0x0600F800` = BG0 screen base 31 (`0x06000000 + 31*0x800`), 与 Op_OpenWindow 完全一致。

### 3.2 卡点 A (主): 目标含 2 条不可达指令, 源码形态未复现
目标 0x08051588 (态 5 入口) 有一段**永远不执行**的代码:

```
08051588: ldr r4,=0x03000E70 ; strh/ldrh ...
08051590: ands r0,r1 ; lsls r0,r0,#0x10 ; lsrs r3,r0,#0x10   ; r3 = flags & 0x40 (HImode)
0805159C: cmp r3,#0
0805159E: beq 0x080515A6          ; ==0 → 继续
080515A0: b  0x08051A06          ; !=0 → 返回 0
080515A2: movs r0,#1              ; <-- 不可达
080515A4: cmp  r0,#0              ; <-- 不可达
080515A6: bne 0x080515A6 (自跳); 若不等 → 继续
```

`movs #1; cmp #0; bne L` 是"测试常量 1"的死代码。全 ROM 仅本函数有此形态
(`rg` 全 asm/matchings 零命中)。**穷举约 60 种源码写法均无法让当前 agbcc 生成它**:
`if (1)` / `while(1)` / `do..while(0)` / `for(;;)` / `switch(1){case 1:}` / 布尔变量
`u16 v=1; if(v)` / `if((v=1))` / `if(1&&x)` / `status==0 && 1` / 嵌套 if(1) 两层深 /
`goto`+label / 函数作用域常量变量 (0x40 与 1 各一组, 含"跨 case 存活") / 复合条件 /
`&&` 短路 / 三元 / 空转 for 等 (见 `.scratch/gpnux/probe*.py` 全部返回 no)。

**推测**: 目标来自某个把常量赋给变量、再测试该变量、且该变量因跨块存活或寄存器压力
未被 GCC 常量折叠的源码; 或目标 agbcc 构建在 `-fprologue-bugfix`/`-O2` 下对某形态
(疑似 `while(1)` 包住整个 token 分派) 的产物。当前工具链无法复现, 与 sub_805063C 挂起
note 里"疑 GCC2 构建版本差异"同类 (docs/progress.md)。

**该死代码本身不改变行为** (等价于 `if (status == 0)`) —— 所以候选在语义等价前提下
只拿到 1291/1416 的分数, 且缺 72 B 主要是这 2 条 + 寄存器 home 级联。

### 3.3 卡点 B: 高位寄存器 home 与 tilemap 指针 r8 复用
目标把 `0x02005800` 基址先装入 **r8** 并全程复用 (态 0 中 r8 被重赋为 `0x0600F800`,
两段清屏各自用 r8), 把 `0x40` 常量装入 **sl** 用于全部 flag 置位, arg0 留 ip/r4。
候选的全局分配整体差 1-2 格 (与 sub_801D378 挂起时的 tie 同类)。这属于 GCC2
global-alloc 的 allocno PRI 排序, 需在卡点 A 解开后随结构变化重排。
