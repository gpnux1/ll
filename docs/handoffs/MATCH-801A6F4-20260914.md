## 2. 核心架构与 GCC 2.95 匹配要点

1. **结构体建模 (`BgUnion`)**:
   ```c
   typedef union {
       BgCnt bg;
       u32 word;
   } BgUnion;
   ```
   - case 6/7 采用寄存器内按位组合（`bgcnt.bg.Priority = val & 3; ... REG_BG1CNT = bgcnt.word;`）；
   - case 8 采用指针别名强制栈内存化写回（`((BgCnt *)&bgcnt)->Priority = head->f_2A; ... REG_BG3CNT = *(u16 *)&bgcnt;`），完美复现 GCC 2.95 针对 32 位栈槽的多字节 RMW 与 `ldrh`。

2. **破除历史 Hack 与关键卡点破局**:
   - 历史版本困于手凑 mask、宏黑魔法与手写汇编，在 case 8 入口产生 `subs r0, #7`（因持久变量导致 CSE 展开 `3 - 7 = -4`）。
   - **根本破局**: `BgCnt` 中 `Priority` 字段定义为 2 位位域 (`u16 Priority : 2;`)。
     直接写 `((BgCnt *)&bgcnt)->Priority = head->f_2A;` 时，GCC 2.95 前端在对 2 位位域求值赋值时**自动**将其与 `3` 进行位与截断，其求值序为：
     ```arm
     mov  r1, ip
     adds r1, #0x2a
     movs r0, #3
     ldrb r1, [r1]
     ands r1, r0
     ```
     并且由于 `3` 是匿名即时数，不会残留为持久变量，后续清理位域时自然生成：
     ```arm
     movs r0, #4
     negs r0, r0
     ```
     与目标汇编 100.00% 完全吻合！0 字节偏差！

3. **标准宏对齐**:
