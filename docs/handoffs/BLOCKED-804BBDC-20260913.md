## 语义 (E2, 4 个调用者交叉验证)
遍历 OBJ 调色板动画表槽 `[start, start+count)`:
- `ctrl & 0xF == 1` (已是流式动画) → 跳过。
- `mode == 2`: 在槽位挂 `ctrl=0x31` 的流式动画 (sub_804C638 刷新), 写入 clamped RGB。
- `mode == 3`: 从 `field6` 起找第一个空闲调色板槽 (查 `gUnk_03000AE2` 位图, 上限 0xF);
  找到则 `sub_804C5B8` 占用 + `sub_804C638` + `ctrl=0x11`; 找不到则 `ctrl=0xFF, palSlot=-1`。
- RGB (r/g/b) 先 clamp 到 0x1F (仅上界), 写入 `dR/dG/dB`; `counter/frameIdx/shift = 0`。

调用者: `sub_8020D50`(闪白, mode3), `sub_8023820`/`sub_8035360`/`sub_803A8D0`(演出, mode2)。

## 卡点: GCC2.9 寄存器分配 (frame +4)
候选 `permuter/sub_804BBDC/base.c` 逻辑完整、总长 376B (与目标等长), 但:
- 目标 `sub sp,#0x18` (6 栈槽); 候选 `sub sp,#0x1c` (7 栈槽, **多 4 字节**)。
- 目标把三个 clamped 颜色存 `sl`/`r9(sb)`/`r7` (callee-saved), 不落栈;
  候选把 `r`(arg2) 溢出到 `[sp+8]`, 占掉第 7 槽。
- 非 bl 差异 ~308 字节, 主要是 arg5-8 读取偏移 (+0x38 vs +0x3c, 随 frame 漂移) 与循环体寄存器 home。

已试 (均无改善): 参数 signedness (s8/u8)、显式 `cr/cg/cb` 局部、`start<<4`/`first` 预计算、
`entry` 移入循环、`empty` 变体。permuter 短跑未收敛。
