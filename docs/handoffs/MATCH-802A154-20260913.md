## 关键 GCC2.9 形状
1. **case19 用 `((void (*)(u8, int, int))sub_801A3A8)(1, -0x23, -5)`**: 声明原型是
   `(u8,u16,u16)`, 负数常量会被折进字面池; 强制 `int` 形参让 GCC 用 `movs #0x23; negs` 物化
   (与已匹配的 `sub_8029BF8` 同款, 见 src/event_actor.c 既有调用点)。这一处修复让 bytecmp 从
   1337B 骤降到 153B。
2. **case34 的 `gUnk_03000820 = 0x23` 必须在第二个 if 内**:
   ```
   if (headB.kindFlags & 0x1000) { obj->state &= 0xDFFF; gUnk_03000820 = 0x23; }
   ```
   写成无条件赋值会让 `beq` 位移错 (150→148 之外, 语义错)。
3. **`gUnk_0839DF90[idx*2+1]` 写成 `(gUnk_0839DF90 + 1)[idx*2]`**:
   让 GCC 把 +1 加到基址寄存器而非索引, 对齐目标的 `adds r2,#1; adds r0,r0,r2`。
4. case18/21/22/28/30 的 `(u8)(0x10 - x)` 显式截断; 各 case 计数++ 共享尾块由正极性写法驱动。
