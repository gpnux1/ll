## 2. 语义（已全解）

```text
MovePlayer(px, py, dir, step):
  if gDialogueActive || gWarpAnimState: return 0
  gMapZoneType = 0xFF
  baseX = *px; baseY = *py
  if step == 0:
      if MapZone_FindAt(baseX, baseY) != 0: MapZone_Trigger()
      return 0
  if gCurrentMapId == 0x19 && Party_AnyEquip():
      ScriptPump_JumpToEntry(10, 2); return 1
  stepX = gWalkDirVectors[dir*2]     * step
  stepY = gWalkDirVectors[dir*2 + 1] * step
  if MapZone_FindAt(baseX+stepX, baseY+stepY) != 0 && MapZone_Trigger() != 0: return 0
  tile = MapTile_At(baseX+stepX, baseY+stepY)
  if tile == NULL: return 0
  collide = MapTile_CollisionBits(tile, baseX+stepX, baseY+stepY)
  if (collide & 0xFF) == 0: goto accept
  switch (dir):                      // 主方向被挡，按碰撞位做"贴墙滑动"
    case 1/5/7/3 (正交): 两次尝试，各自内联 MapTile_At + CollisionBits 检查
    case 2/4/6/8 (对角): 第一次尝试内联检查，第二次尝试落到共享尾块
    其他: return 0
  // 共享尾块（对角二次尝试）
  tile = MapTile_At(baseX+stepX, baseY+stepY)
  if tile == NULL: return 0
  if (MapTile_CollisionBits(tile, baseX+stepX, baseY+stepY) & 0xFF) != 0: return 0
accept:
  for i in 2..17:  与 gActors 做 0x20 × 0x10 的 AABB 相交 → return 0
  for i in 0..15:  与 gChestObjects 做 AABB 相交 → return 0
  *px = baseX + stepX; *py = baseY + stepY; return 1
```

### 关键编译器事实（本轮实证，非推测）

1. **HImode 寄存器约定**：用一个最小探针（`.scratch/nova2/probe.c`）实测确认，agbcc 对
   `newX = baseX + stepX; tile = MapTile_At(newX, newY); collide = MapTile_CollisionBits(tile, newX, newY);`
   生成
   `add r0,r0,r2 / lsl r5,r0,#0x10 / asr r0,r5,#0x10 ... lsr r1,r5,#0x10`
   即：HImode 以"左移 16"形式存在寄存器里，s16 形参用 `asrs`、u16 形参用 `lsrs`，`lsls` 被 CSE。这与目标完全一致。
2. **赋值顺序敏感**：非零分量必须先赋值。正交 case（stepY 恒 0）→ `stepX` 先；纵向/对角首次尝试（stepX 恒 0）→ `stepY` 先。反向顺序 v971/v986 均变差。
3. **`newX`/`newY` 必须是变量**：去掉后（v950）分数劣化到 28948。

## 5. 剩余差异（v1000，38 条双侧不同）

1. **对角 case 的 `asrs r0,r5,#0x10` vs `lsrs r6,r0,#0x10`**（0x33c / 0x382 / 0x41a，3 处）
   对角 case 里 s16 形参仍被编译成零扩展，说明该处 `MapTile_At` 调用仍未留在 case 体内。
2. **对角 case 取值顺序**（0x24e / 0x2b2）：TGT `mov r3,sl; ... lsrs r7,r2,#0x10`，CUR `lsrs r7,r0,#0x10; mov r5,r9`。
3. **0x392**：TGT `lsls r6,r5,#0x10`，CUR `mov r1,sl`。
4. **accept 段 Y 中心外提**（0x45e / 0x460）：TGT 在循环外算 `asrs r0,r7,#0x10; adds r4,r0,#0; adds r4,#8`，循环内 `adds r1,r0,r4; subs r0,#8 / adds r0,#0x10`；CUR 在循环内重算。已试 `yc = stepY + 8`（v1001，12549，更差）与内联 `+8-8`（v1002，持平），**未解决**。
5. **宝箱循环**（0x4b6 / 0x4da）：TGT 把 `baseX` 与 `stepX` 都溢栈（0x2c/0x30）并在循环内 `ldr` 两个；CUR 把 `stepX` 留在 `ip`。
6. **栈槽编号**：槽数已一致（0x34），但 CUR 的 0x20/0x24/0x28/0x2c/0x30 相对 TGT 后移一格。
7. 字面池偏移差（0x58-0x84、0x188、0x53c-0x540）为代码尺寸差异的连带结果，随上面各项收敛会自动消失。
