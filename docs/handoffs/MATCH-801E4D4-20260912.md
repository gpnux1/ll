## 复刻关键 (GCC2.9 形状, 全部已验证)

1. **v 分派必须用 `switch (*(u16 *)((u8 *)entry + 0x10))` 直接 switch 表达式**,
   且 case 0 内的 `= *(u16 *)((u8 *)entry + 0x10)` 重读由扩展基本块 CSE 折回 r3。
   若写成 `u16 v = ...; switch (v)`, GCC 会把 v 分裂成 r0(派发)+r4(使用)两个伪寄存器, 多出 `adds r4, r0, #0`。
2. **case 1 的 idx 计算必须拆成两条语句且中间变量为 s32**:
   `t = *(u16*)(p+0x1A) + 3; idx = t + *(u8*)(p+0x29);`
   - 单语句 `h + 3 + b` 会被 CSE 重结合成 `(b+3)+h` → 字节链先求值, 与目标 (h, baddr, +3, b, sum) 不符;
   - `u16 idx` 两语句会在 `idx += b` 的 HImode 读回时插入中间截断 `lsls/lsrs`;
   - `s32 t` 两语句: h 链先展开、无中间截断、尾块 u16 提取落 r1 —— 三者同时满足。
3. **limit 必须用三元式** `limit = (arg1[0xBE] > 0xA) ? 7 : 5;`
   (init-5 + 条件覆盖的两语句形式会让 `movs r7,#5; mov ip,r7` 排到字节加载之前, 0xd4-0xdd 10 字节错位。
   注意: 上一会话残留的 ll.gba 恰好差在这 10 字节 —— 与本次 fncheck 差异偏移完全一致, 已由本次全量构建修复)。
4. **扣减判断极性**: 目标两处都是 `if (*(s16*)(x+0x6C) - *(s16*)(x+0xB2) <= 0) {清零; wrapped=1} else {减; wrapped=0}`
   —— 回绕块为直落路径, `bgt` 跳到减法块。与已匹配 sub_8020BC0 的早退式写法不同。
5. **入队必须经 `static inline Inl_QueuePushObj` 调用** (语义 = 已匹配的 sub_8020B90):
   手写内联体时 GCC 会把 `i*0xC8` 中间量放 r0 再 `adds r1, r0, r5`; 内联展开才产生目标的
   `adds r1, r4; muls r1, r7; adds r1, r1, r5` 全链原位 r1。static inline 全调用点被集成,
   不产生独立副本, 不影响 .text 布局 (GNU89 inline 语义; 原 ROM 大概率是宏或前置 inline 定义)。
6. **成员地址用整数算术** `(u8 *)(i * 0xC8 + (u32)arg1)` 防指针规范化翻转操作数序 (同经验 150)。
7. **尾部扫描**: `i = 0; if (flags[0] == 1) result = flags[0]; else { while (++i <= 6) {...} }`
   —— `while (++i <= 6)` 产生"自增在头"的循环形; flags[0] 赋值处的重载 (mov r0,sp; ldrb) 是
   load/cmp 与赋值分属两个基本块、局部 CSE 不跨块所致, 属正确形状, 不要"修掉"。
