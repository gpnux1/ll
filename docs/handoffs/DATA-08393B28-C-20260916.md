# DATA-08393B28-C: gUnk_08393B28 类型化命名并搬入 src/data_08393B28.c

- 日期: 2026-09-16
- agent: opencode-08393b28
- 认领: `gUnk_08393B28`
- 状态: 已完成，全量 `make` + `sha1sum -c ll.sha1` 通过

## 1. 目标

把 `0x08393B28` 的战斗对象动画/特效资源表从 ROM blob/linker 绝对符号搬成真实 C 数据定义，并应用已验证的语义字段名与字段类型。

## 2. 类型改动

`include/code_0.h` 中 `ObjAnimEntry` 从：

```c
u32 field_0;
u32 field_4;
u16 field_8;
u16 field_A;
u16 field_C;
u16 field_E;
u16 targetMode;
u8  pad_12[2];
```

改为：

```c
const u16 *animScriptPtr; /* +0x00 -> ObjHead.scriptPtr */
const u8  *palettePtr;    /* +0x04 -> ObjHead.palBitsPtr */
u16        gfxBaseIdx;    /* +0x08 -> ObjHead.gfxBaseIdx */
u16        gfxTotal;      /* +0x0A -> ObjHead.gfxTotal */
u16        field_C;       /* +0x0C -> BattleObj.f_B4 (语义未定) */
u16        field_E;       /* +0x0E -> BattleObj.f_B6 (语义未定) */
u16        targetMode;    /* +0x10 */
u16        pad_12;        /* +0x12, 全表实测 0 */
```

`extern ObjAnimEntry gUnk_08393B28[];` 改为：

```c
extern const ObjAnimEntry gUnk_08393B28[];
```

理由：

- `field_0` 全部为 ROM 命令流头指针，进入 `sub_801B81C` 后写 `ObjHead.scriptPtr`。
- `field_4` 全部落在调色板数据区，进入 `sub_801B81C` 后写 `ObjHead.palBitsPtr`。
- `field_8` 是 `gUnk_087EBE00[gfxBaseIdx + gfxPos]` 的索引基址。
- `field_A` 是分步图形装载总数。
- `field_C/field_E` 只复制到 `BattleObj.f_B4/f_B6`，语义仍有多个消费上下文，暂不强行命名。

## 3. 数据落地

新增 `src/data_08393B28.c`：

```c
const ObjAnimEntry gUnk_08393B28[992] = { ... };
```

内容直接由 `baserom.gba @ 0x08393B28` 提取，992 项 × 0x14 字节，覆盖 `0x08393B28..0x083988A8`。不再使用 `INCBIN` 或 linker 绝对符号提供该表。

## 5. linker 改动

`linker.ld`：

- 删除绝对符号：
  ```ld
  gUnk_08393B28_entries = 0x08393B28;
  gUnk_08393B28 = 0x08393B28;
  ```
- 在 `.rodata` 中按原 ROM 地址插入：
  ```ld
  . = ORIGIN(rom) + 0x393B28;
  src/data_08393B28.o(.rodata);
  . = ORIGIN(rom) + 0x3988A8;
  data/data1d.o(.rodata);
  ```
- 保留 `gUnk_083988A8 = 0x083988A8;` 绝对符号，因为它是相邻的 24 字节动画条目表，不是本次搬移范围。

已运行 `python3 scripts/gen_debug_ld.py --gap "event_hub event_actor"` 重建 `linker_debug.ld`。
