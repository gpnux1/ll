## 2. 结构体定义 (iwram.h, 覆盖视图设计)

```c
typedef struct ItemUseFx {          /* 0x03000DDE..0x03000DEA */
    u8 state; u8 pad_1;              /* +00 PC 0..13; +01 pad (DDF) */
    u16 loopFrom, loopTo;            /* +02 DE0 / +04 DE2 目标 headB 循环帧区间 */
    u8 loopCount, loopsDone;         /* +06 DE4 圈数(3) / +07 DE5 已播圈数 */
    u16 savedF2A;                    /* +08 DE6 保存的 headA.f_1E (obj+0x2A) */
    u8 savedPalSlot, pad_B;          /* +0A DE8 保存的 headA.palSlot (obj+0x35) */
} ItemUseFx;                         /* 0x03000DDF, DE9..DEF 无引用 */

typedef struct BattleFx {            /* 0x03000DF0..0x03000E05 */
    u32 objs[5];                     /* +00 DF0..E03 登记对象指针, [0]=模板 */
    u8 objCount;                     /* +14 E04 */
    u8 state;                        /* +15 E05 PC 0/1/2/4 */
    u8 pad_16[2];                    /* +16 E06/E07 无引用 */
} BattleFx;

typedef struct BattleDrops {         /* 0x03000E08..0x03000E30 */
    BattleDropEntry items[10];       /* +00 E08..E2F {itemId,count,pad_2}×10 */
    u8 count;                        /* +28 E30 已用记录数 */
} BattleDrops;
```

extern 基址: `gItemUseFx`(0x03000DDE) / `gBattleFx`(0x03000DF0) / `gBattleDropsBlk`(0x03000E08),
linker.ld 同步登记。

**容量 10 的 E0 证明**: items[10] 末尾恰与 count(E30) 相邻; BattleDrops_Roll 追加记录无上界
检查 (>10 个不同道具会覆写 count — 未观察到的病态路径, 候选 C 不应复刻越界)。

## 3. ⚠ 匹配输入约定 (重要)

**扁平符号与结构体视图并存, 双方都是真值**:
- 扁平 extern (gItemUseFxState/gBattleFxObjs/gBattleDrops/gBattleDropCount/...) =
  已匹配代码正在使用, 且 **ROM 字面量 (0x03000DDE/DE0/DE2/DE4/DE5/DF0/E04/E05/E08/E30)
  与之一一对应**。
- 结构体基址 (gItemUseFx/gBattleFx/gBattleDropsBlk) = 布局文档/语义分组, 无代码使用。

给 BattleDrops_Roll / ItemUseFx_RunWeapon 写候选 C 时 **必须用扁平符号**: ROM 以
`ldr rX, =0x03000E30` 这类独立字面量访问每个地址; 若写 `gBattleDropsBlk.count` 会生成
`基址+0x28` 偏移寻址, 字面量池内容与指令形状都变, 字节匹配必挂。结构体用于读懂语义,
扁平符号用于落字节。
