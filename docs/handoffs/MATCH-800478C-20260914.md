## 2. 语义与业务逻辑 (E2 级证据)

`CutsceneAnim_PlayFrame` 负责为一个给定的实体/卡片/怪物 ID 准备动画资源并把主展示实体 `gActors[0]` 摆放在当前相机视口内的合适相对位置：

1. **动画表项索引获取**:
   - 若 `animEntityId > 0x7F`: 实体属于特殊过场实体（ID ≥ 128），从 `gUnk_0839C80C[animEntityId - 0x80]`（64 字节/项）偏移 0 处读取 16 位动画索引 `animIdx`；
   - 若 `animEntityId <= 0x7F`: 实体属于标准敌人（ID 0..127），从 `gUnk_083989FC[animEntityId]`（44 字节/项，敌人战斗数据表，首项对应敌人 0）偏移 `+0x1A` 处读取 16 位动画索引 `animIdx`。
2. **过场动画系统槽 0 装配与解压**:
   - `gCutsceneAnimScripts[0]` 设为效果表项 `gUnk_08393B28[animIdx].field_0`；
   - `gVramBufferPointers[0]` 设为 `0x02020000` (`CUTSCENE_ANIM_BASE`)；
   - `gCutsceneAnimFlags[0]` 置 `0x80`；
   - `gCutsceneAnimSlots[0]` 设为 5；
   - `gCutsceneAnimPals[0]` 设为调色板地址 `gUnk_08393B28[animIdx].field_4`；
   - 调用 `LZ77UnCompWram(gUnk_087EBE00[gUnk_08393B28[animIdx].field_8], CUTSCENE_ANIM_BASE)` 将动画图块解压到 VRAM 缓冲槽 0。
3. **视口相对坐标定位**:
   - 对于特殊过场实体 (`animEntityId > 0x7F`):
     - `switch (animEntityId)` 处理 ID 0x81..0x89（通过 9 项跳转表分派）：
       - `0x81`: `x = camX + 160, y = camY + 104`
       - `0x82`: `x = camX + 144, y = camY + 104`
       - `0x84`: `x = camX + 160, y = camY + 120`
       - `0x85`: `x = camX + 160, y = camY + 112`
       - `0x88`: `x = camX + 133, y = camY + 124`
       - `0x89`: `x = camX + 144, y = camY + 108`
       - 默认/其它: `x = camX + 136, y = camY + 104`
   - 对于标准敌人 (`animEntityId <= 0x7F`):
     - `x = camX + 136`
     - `switch (gUnk_083989FC[animEntityId].yOffsetMode)`:
       - `2`: `y = camY + 104 (0x68)`
       - `1`: `y = camY + 96  (0x60)`
       - 默认: `y = camY + 88  (0x58)`

## 3. GCC 2.95 编译特征与匹配要点

1. **`slot = 0` 分配到 `ip` (r12)**:
   函数声明局部变量 `u32 slot = 0;`。由于 `r4..r7` 在前序和后续流程中全部被占用，GCC2.95 将 `slot` 分配到暂存寄存器 `ip`，在调用 `LZ77UnCompWram` 前由 `ip` 展开为各个数组寻址。
2. **`LZ77UnCompWram` 第二实参的常量重用**:
   在给 `gVramBufferPointers[slot]` 赋值 `0x02020000` 时加载了 `r1 = 0x02020000`，GCC2.95 识别到该常量在调用 `LZ77UnCompWram` 时仍驻留在 `r1` 中，直接作为第二形参传入，省去了二次 ldr。
3. **`switch` 语句展开顺序**:
   敌人 Y 偏移分支为 3 项 switch：`case 2` 写在 `case 1` 之前，使得 GCC2.95 的 sparse-switch 启发式判定先匹配 `case 1` 跳出、再匹配 `case 2` 直通当前代码块，与目标汇编完全咬合。
4. **原型声明对齐**:
   `include/code_0.h` 中原先为空参数列表 `void CutsceneAnim_PlayFrame();`，在 GCC 2.95 下匹配 `u16` 实参会因默认整数提升规则触发 `conflicting types`，同步更新为 `void CutsceneAnim_PlayFrame(u16 animEntityId);`。
